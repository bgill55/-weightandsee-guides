OneCLI: The Open-Source Agent Harness That Keeps Your AI Truly Local

This guide demonstrates how to set up and use OneCLI, an open-source sandboxed agent harness for local LLM deployments, focusing on security, cost reduction, and compliance.

By Weight and See August 20, 2026 5 Steps

🎯 Key Takeaways

  • 1OneCLI isolates LLM agents in Docker containers, ensuring no data leaves the local network.
  • 2It uses a zero-trust proxy to manage secrets and tokens, eliminating credential exposure.
  • 3OneCLI supports various open-source models and can be easily configured to switch between them.
  • 4Local deployment with OneCLI reduces cloud costs and latency compared to cloud APIs.
  • 5It provides monitoring and security features like mutual TLS for production environments.

📋 Prerequisites

  • Docker and Docker Compose installed on your system.
  • Basic understanding of Linux commands and networking.

📝 Step-by-Step Guide

1

Clone and Set Up OneCLI

Clone the OneCLI repository and set up the Docker stack using Docker Compose. This step initializes the environment and pulls the necessary images.

git clone https://github.com/onecli/onecli.git && cd onecli && docker compose up -d
2

Configure the Proxy

Edit the `onecli.yaml` file to define allowed endpoints, secret vault path, and model mappings. Save and restart the Docker stack to apply changes.

Edit `onecli.yaml`:
model: llama-4
image: llama4:latest

Save and restart with: docker compose restart
3

Launch an Agent

Run a command to launch an agent, specifying the model and prompt. The proxy handles token injection and communication with the container.

onecli run --model llama-4 --prompt "Summarize the quarterly report"
4

Manage Secrets

Use environment variables to inject secrets. The proxy reads and substitutes these variables, ensuring they are not stored in logs or snapshots.

Example `.env` file:
API_KEY=abcd1234
5

Monitor and Secure

Utilize Prometheus exporter for real-time monitoring of container performance. Consider enabling mutual TLS for production environments to encrypt internal traffic.

Point Grafana at http://localhost:9090/metrics for monitoring.
For TLS, generate certificates, mount them, and set tls.enabled: true in onecli.yaml.

💡 Pro Tips

Pro Tip: Ensure Docker runs with --privileged or the user is in the docker group for namespace permissions.
Pro Tip: Allow intra-cluster traffic on the proxy port (default 8080) in your firewall.

⚠️ Common Pitfalls

Watch Out: Mismatched network namespace permissions may cause permission denied errors.
Watch Out: Verify Docker daemon settings and user group for successful container execution.

❓ Frequently Asked Questions

How do I update the model used by OneCLI?

Edit the `onecli.yaml` file and update the `model` and `image` fields accordingly. Save and restart the Docker stack to apply the changes.

What is the purpose of the zero-trust proxy in OneCLI?

The zero-trust proxy acts as a secure intermediary between LLM agents and external services. It manages secrets, injects temporary tokens, and enforces strict egress rules to prevent unauthorized access.

How can I enable mutual TLS for production?

Generate a certificate pair, mount them into the proxy container, and set `tls.enabled: true` in `onecli.yaml`. This encrypts internal traffic for enhanced security.
