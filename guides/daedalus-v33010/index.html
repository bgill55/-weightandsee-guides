Daedalus v3.30.10

This guide walks through using Daedalus v3.30.10, a terminal‑based local‑first multi‑agent workbench that automates code generation, test creation, and Git workflow. It demonstrates how to prompt Daedalus to add functions, generate Jest tests, and merge changes automatically while preserving best practices.

🎯 Key Takeaways

  • 1Daedalus eliminates the need for manual JSON configs by parsing project context through a simple slash‑spec prompt.
  • 2The tool automatically creates a test‑first implementation: it writes Jest tests first, then generates the production code to satisfy them.
  • 3Git integration is seamless; Daedalus opens feature branches, commits, creates PRs, and merges to main while squashing commits.
  • 4State persistence via MCP roots allows incremental feature development across sessions.

📋 Prerequisites

  • Node.js (≥14) and npm or yarn installed
  • Git configured with remote repository access
  • A local JavaScript/TypeScript project with a `package.json` and Jest installed

📝 Step-by-Step Guide

1

1. Install the Daedalus CLI

Download and install the latest Daedalus binary from the official repository. The CLI is available as a pre‑compiled binary for Linux, macOS, and Windows. After installing, add it to your PATH.

curl -L https://github.com/daedalus/cli/releases/download/v3.30.10/daedalus-v3.30.10-linux-amd64.tar.gz | tar xz && mv daedalus-v3.30.10-linux-amd64/daedalus /usr/local/bin/
# Verify installation
 daedalus --version  # outputs 3.30.10
2

2. Bootstrap the Daedalus Workspace

Navigate to your project root and run the bootstrap command. This loads project rules and starts the MCP filesystem in the background. The slash‑spec syntax will be ready for use immediately.

cd /path/to/your/project
 daedalus bootstrap
# You should see logs like:
# [INFO] Project rules loaded
# [INFO] MCP filesystem active
3

3. Prompt Daedalus to Add a Helper Function

Use a simple natural‑language prompt to ask Daedalus to create a new helper. The CLI interprets the request, locates the appropriate file, and prepares an implementation plan.

daedalus prompt "Add a helper function to validate semantic version strings"
# Expected output:
# • Adding function validateVersion in src/utils/version.js
# • Generating Jest tests first
4

4. Generate Tests and Implementation

Daedalus will automatically write a Jest test file and then generate the implementation code that passes those tests. No manual test writing is required.

# Daedalus runs internally; the result will be files:
# tests/utils/validateVersion.test.js
# src/utils/validateVersion.js
# Verify tests:
 npm test
# All tests should pass
5

5. Let Daedalus Handle Git Workflow

Once the code and tests are in place, Daedalus will create a feature branch, commit the changes, open a PR, and merge to main if checks pass. It also cleans up the feature branch afterward.

daedalus git --auto-merge
# The CLI will output something like:
# • Created branch feature/validate-version
# • Committed 3 files
# • Opened PR #42
# • Merged to main and deleted feature branch
6

6. Review the Delivery Log

Check Daedalus’s delivery log to confirm that all spec goals have been met and the feature is fully integrated.

daedalus delivery-log
# Sample output:
# ✅ Feature: validateVersion added
# ✅ Tests passed
# ✅ PR merged into main

💡 Pro Tips

Pro Tip: Use the `daedalus config` command to adjust default test frameworks or linting rules if your project deviates from Jest.
Pro Tip: When working on large refactors, split prompts into smaller, focused requests to keep the implementation plan manageable.
Pro Tip: Leverage the `daedalus log` command to audit previous changes and see the reasoning behind each auto‑generated patch.

⚠️ Common Pitfalls

Watch Out: Pitfall 1: Over‑reliance on auto‑generated code can mask subtle bugs—always review generated logic before merging.
Watch Out: Pitfall 2: If your repository contains non‑standard test runners, Daedalus may default to Jest; configure the `--test-framework` flag accordingly.

❓ Frequently Asked Questions

Does Daedalus support TypeScript projects?

Yes, Daedalus automatically detects TypeScript files and generates `.ts` files with proper typings when creating functions or tests.

Can I customize the test framework Daedalus uses?

Use the `--test-framework` flag or edit the `daedalus.config.json` to specify frameworks such as Mocha, Vitest, or Jest.

How does Daedalus keep state across sessions?

It uses MCP (Multi‑Component Persistence) roots stored in a hidden `.daedalus` directory that caches project context and spec goals.

What happens if a generated test fails?

Daedalus will stop the implementation step and display a diff. You can edit the failing test or the implementation manually and re‑run `daedalus prompt`.

Is there a way to rollback a merge performed by Daedalus?

Because commits are squashed and merged cleanly, you can use `git reflog` to find the previous state or use GitHub's revert PR feature to undo changes.
