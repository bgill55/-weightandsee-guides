  • 2The tool is test‑driven: it writes Jest tests first, then generates implementation code to satisfy those tests.
  • 3Git workflow is fully automated—Daedalus opens a PR, squashes commits, merges into main, and cleans the feature branch.

📋 Prerequisites

  • Node.js 18+ (required for Jest and Daedalus CLI)
  • Git configured with a remote (e.g., GitHub)
  • Basic familiarity with terminal usage and JavaScript testing

📝 Step-by-Step Guide

1

Step 1: Install the Daedalus CLI

Download and install the latest Daedalus binary or use npm. The CLI is cross‑platform and ships with the MCP filesystem bundled.

```bash
# Using npm
npm install -g @daedalus/cli

# Or download the binary
curl -L https://daedalus.ai/download/daedalus-v3.30.10-linux-x64 -o daedalus
chmod +x daedalus
mv daedalus /usr/local/bin/daedalus
```
2

Step 2: Initialize your project with a slash spec

Create a new project directory, navigate into it, and run the init command. The slash spec automatically loads project rules and starts the MCP filesystem in the background.

```bash
mkdir my-app && cd my-app

daedalus init \
  --spec "/project/spec" \
  --root .
# The CLI will output: "Project rules loaded. MCP filesystem running."```
3

Step 3: Prompt Daedalus to add a helper function

Use the CLI prompt to request a new helper. Daedalus parses the context and knows where to place the new logic.

```bash
# Ask for a version validation helper
 daedalus prompt "Add helper function to validate semantic version strings in src/utils/version.ts"
```
The CLI will print a plan and generate the file skeleton.
4

Step 4: Auto‑generate Jest tests and implementation

Daedalus creates a Jest test file first, then writes implementation code that satisfies those tests. The test file is placed in the appropriate test directory.

```bash
# After the previous prompt, Daedalus outputs:
# ✅ Created test file: tests/utils/validateVersion.test.ts
# ✅ Created implementation: src/utils/version.ts

# Run the tests to verify
npm test
# Jest will report the tests pass instantly. ```
5

Step 5: Commit, push, and merge via auto‑PR

Daedalus automatically creates a feature branch, commits the generated files, opens a PR, and merges it back into main when checks pass. It cleans up the branch after merging.

```bash
# Daedalus handles this behind the scenes:
# 1. Creates branch: feature/add-version-helper
# 2. Commits changes
# 3. Opens PR on GitHub
# 4. Squashes and merges into main
# 5. Deletes feature branch

# To see the log:
daedalus delivery-log
```
The output confirms the feature is integrated.

💡 Pro Tips

Pro Tip: Use `daedalus watch` to keep the MCP filesystem in sync while you edit files manually.
Pro Tip: Configure `daedalus config set git.remote https://github.com/your-org/your-repo.git` to avoid prompts for remote URLs.
Pro Tip: Add custom rules to the slash spec for linting or code style to keep the generated code consistent with your project.

⚠️ Common Pitfalls

Watch Out: Pitfall 1: Ignoring the generated Jest tests may lead to untested code if you edit manually. Always review tests first.
Watch Out: Pitfall 2: Running `daedalus` on a repository without a proper Git remote will stall the PR step—ensure `git remote add origin …` is set up.
Watch Out: Pitfall 3: Over‑relying on auto‑PR can mask merge conflicts if multiple contributors modify the same file concurrently; use feature branches wisely.

❓ Frequently Asked Questions

Can I use Daedalus with a non‑JavaScript codebase?

Yes. Daedalus supports multiple languages via language adapters. Specify the language in your slash spec, and the tool will generate appropriate test and implementation files.

How does Daedalus determine where to place the helper function?

It parses the current repository structure, follows naming conventions from the spec, and places new files in the correct directory tree based on project rules.

What happens if the auto‑generated tests fail?

Daedalus will stop the implementation step and prompt you to fix the logic. You can edit the code manually or re‑prompt for a different implementation.

Can I customize the Git merge strategy?

Yes. Use `daedalus config set git.mergeStrategy squash` or `rebase` to override the default squash merge.

Does Daedalus support CI integrations?

The generated test files are standard Jest, so any CI pipeline that runs `npm test` will work. Daedalus also emits a delivery log that can be parsed by custom CI scripts.
