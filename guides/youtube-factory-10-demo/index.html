This guide walks you through the core components of YouTube Factory 1.0, demonstrating how to configure image diffusion models, run ultra‑fast generation pipelines, and add voice‑over capabilities via a plug‑and‑play HTTP TTS provider.

🎯 Key Takeaways

  • 1YouTube Factory abstracts hardware dependencies, allowing DiffusionGemma 26B and FLUX 2 to run on local GPUs without extra setup.
  • 2Optimized GPU pipelines deliver sub‑second image synthesis, while containerized services provide horizontal scalability.
  • 3A single, reproducible configuration snapshot captures all model parameters for deterministic, repeatable outputs.
  • 4The VOICEOVER stage uses Supertonic’s HTTP‑based TTS engine, eliminating the need for heavyweight voice SDKs.
  • 5The modular architecture lets you swap diffusion or TTS providers by simply editing the config or exposing a new HTTP endpoint.

📋 Prerequisites

  • A GPU‑enabled machine with Docker (or another container runtime) installed.
  • Basic familiarity with command‑line interfaces and JSON/YAML configuration files.

📝 Step-by-Step Guide

1

Step 1: Select and configure image diffusion models

Open the $3 configuration panel and specify the desired diffusion providers. The panel maps each provider to its runtime environment, ensuring the correct container image and GPU resources are allocated.

ytfactory config set --model diffusiongemma-26b --fallback flux-2
# Example snippet of the generated config file
{
  "image": {
    "provider": "diffusiongemma-26b",
    "fallback": "flux-2",
    "gpu": "auto"
  }
}
2

Step 2: Run the image generation job

Execute the generation command. YouTube Factory launches a containerized service that streams the model to the GPU, producing an image in under a second. Logs include timestamps for performance verification.

ytfactory run image --prompt "futuristic cityscape at sunset"
# Sample log output
[2026-06-14T04:49:40.335622] INFO: Image generation started

Step 3: Add the VOICEOVER stage with Supertonic

Configure the voice provider to use Supertonic’s HTTP endpoint. The stage is decoupled, so you can replace it with any TTS service that conforms to the same API contract.

ytfactory config set --stage voiceover --provider supertonic --endpoint https://api.supertonic.ai/v1/tts
# Minimal VOICEOVER config snippet
{
  "voiceover": {
    "provider": "supertonic",
    "endpoint": "https://api.supertonic.ai/v1/tts",
    "language": "en-US",
    "style": "narrative"
  }
}
4

Step 4: Execute the full production pipeline

Run the combined image‑and‑voice workflow. The platform stitches the generated image with the synthesized audio, producing a ready‑to‑publish video asset.

ytfactory run full --config ./factory_snapshot.json
# Log excerpt showing both stages

5

Step 5: Save and reuse the configuration snapshot

After a successful run, export the full configuration. This snapshot can be version‑controlled and reused to guarantee identical outputs for future content batches.

ytfactory config export --output factory_snapshot_v1.json

💡 Pro Tips

Pro Tip: Export a configuration snapshot after each successful run; store it in Git to track model version changes over time.
Pro Tip: Monitor GPU utilization with `nvidia-smi` while the container is active to ensure you’re not hitting memory limits.
Pro Tip: When swapping TTS providers, keep the request/response schema identical to avoid breaking the pipeline.

⚠️ Common Pitfalls

Watch Out: Pitfall 1: Mismatched GPU driver versions – leads to container start‑up failures. Verify driver compatibility before installing new diffusion models.
Watch Out: Pitfall 2: Incorrect HTTP endpoint for a custom TTS provider – results in silent voiceover failures. Test the endpoint with a curl request before updating the config.

❓ Frequently Asked Questions

What does the $3 configuration panel refer to?

It is the internal UI/CLI component that aggregates all model‑selection and runtime settings into a single JSON snapshot, identified as configuration version 3.

Can I use a different diffusion model than DiffusionGemma or FLUX 2?

Yes. Add the model’s container image and GPU requirements to the config file, then reference it in the `--model` flag. The platform will handle the rest.

How does YouTube Factory achieve sub‑second latency?

By pre‑loading models into persistent GPU containers, using optimized inference kernels, and streaming results directly to the host process without intermediate disk writes.

Is it possible to run multiple generation jobs concurrently?

Absolutely. The containerized services are stateless and can be scaled horizontally; just increase the replica count in the orchestration layer (e.g., Docker Compose or Kubernetes).

What do I need to do to add a new TTS provider?

Expose an HTTP endpoint that follows the same request/response schema as Supertonic, then update the `voiceover.provider` and `voiceover.endpoint` fields in the configuration.
