📋 Prerequisites

  • Linux machine with an Nvidia RTX GPU (RTX 4090 recommended, RTX 3080 acceptable with 3‑bit quantization).
  • CUDA 12.x, cuDNN, and NVIDIA driver 550+ installed.
  • Docker Engine 20+ and Docker Compose installed.
  • Python 3.10+ and pip for dependency installation.

📝 Step-by-Step Guide

1

Step 1: Prepare the Hardware & Drivers

Ensure your GPU drivers, CUDA toolkit, and cuDNN libraries are up to date. Verify the GPU is recognized by running `nvidia-smi`. Install Docker and Docker Compose for container deployment.

```bash
# Install NVIDIA drivers (Ubuntu example)
sudo apt update && sudo apt install -y nvidia-driver-550 nvidia-dkms-550 nvidia-utils-550
# Verify GPU
nvidia-smi
# Install Docker
sudo apt install -y apt-transport-https ca-certificates curl gnupg lsb-release
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /usr/share/keyrings/docker-archive-keyring.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/docker-archive-keyring.gpg] https://download.docker.com/linux/ubuntu $(lsb_release -cs) stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
sudo apt update && sudo apt install -y docker-ce docker-ce-cli containerd.io
sudo usermod -aG docker $USER
# Log out/in to apply group changes
```
2

Step 2: Clone Portable Computer & Install Dependencies

Download the Portable Computer repo, create a virtual environment, and install Python dependencies. The repository bundles the agent harness, inference engine, and model weights.

```bash
git clone https://github.com/perplexity-ai/portable-computer.git
cd portable-computer
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
# Optionally pull pre‑bundled model weights
python scripts/download_models.py
```
3

Step 3: Run Quantized Llama 4 Inference

Launch the Llama 4 model quantized to 4‑bit. The command starts a local inference server that responds via the same REST API as GPT‑5.5.

```bash
python -m llama.run --model llama4 --quant 4bit --port 8080
# Test with curl
curl -X POST http://localhost:8080/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"llama4","messages":[{"role":"user","content":"Hello"}]}'
```
4

Step 4: Benchmark Latency and Throughput

Use the provided benchmark script to send 150‑token prompts and measure average latency under different concurrency levels. The script logs token counts, response times, and power usage.

```bash
# Run a single‑request benchmark
./benchmark.sh --prompt "What is AI?" --tokens 150
# Run a concurrency benchmark with 4 workers
./benchmark.sh --prompt "Explain quantum computing." --tokens 150 --workers 4
# The script outputs JSON with avg_latency, max_latency, and power_consumption
```
5

Step 5: Deploy via Docker for Production

Pull the pre‑built Docker image or build locally, then expose the inference endpoint. Docker’s single command mirrors the cloud API signature, making migration painless.

```bash
# Pull the latest image
docker pull perplexityai/llama4:latest
# Run the container
docker run -d --gpus all -p 8080:80 perplexityai/llama4:latest
# Verify endpoint is reachable
curl http://localhost:8080/v1/chat/completions -H "Content-Type: application/json" -d '{"model":"llama4","messages":[{"role":"user","content":"Hello"}]}'
```

💡 Pro Tips

Pro Tip: Use `uvicorn --workers 4 --port 8080 main:app` to increase concurrent request handling on high‑core CPUs.
Pro Tip: Enable GPU memory pooling (`torch.cuda.set_per_process_memory_fraction(0.8, 0)`) to avoid out‑of‑memory errors when scaling up.
Pro Tip: Run the quantization tool before model deployment to save VRAM: `quantize_tool --bits 3 --target gpu --model qwen3.8`.
Pro Tip: Add a `--dry-run` flag to the inference script to validate PII filtering before production.
Pro Tip: Keep the Docker image updated nightly via a GitHub Actions workflow that rebuilds from the latest repo commit.

⚠️ Common Pitfalls

Watch Out: Pitfall 1: Forgetting to install CUDA/cuDNN can lead to `RuntimeError: CUDA not available` even with a GPU.
Watch Out: Pitfall 2: Using 4‑bit quantization on an RTX 3080 without disabling `torch.backends.cudnn.benchmark` may cause occasional stalls.
Watch Out: Pitfall 3: Exposing the inference endpoint without rate limiting can lead to denial‑of‑service from accidental overload.

❓ Frequently Asked Questions

Can I run the Portable Computer on a Windows machine?

The current release targets Linux. Windows support is planned, but for now you need a WSL2 environment or a native Linux distribution.

What is the maximum model size I can run on an RTX 4090?

With 4‑bit quantization, you can run up to ~27 B parameter models (Qwen 3.8, PPLX 27B). 3‑bit quantization expands this to ~30 B on the same GPU.

How does the system handle concurrent requests?

Launch multiple `uvicorn` workers (e.g., `uvicorn --workers 4`) or use Docker Compose to spin up several service instances. Benchmarks show average latency stays below 2.5 s with four workers.

What are the security guarantees?

The sandbox blocks outbound network traffic by default, and the PII classifier flags any data that would be sent to the cloud. Hybrid escalation requires explicit user approval.

Is there a cost for using the local models?

No token billing occurs. Costs are limited to electricity, GPU depreciation, and any cloud escalation you opt into.
