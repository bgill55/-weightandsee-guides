# compliance_check.py - Basic export compliance screening
import requests

def check_sanctions(entity_name: str) -> dict:
    """Screen entity against OpenSanctions API"""
    url = "https://api.opensanctions.org/match/default"
    payload = {
        "queries": {
            "q1": {
                "schema": "LegalEntity",
                "properties": {"name": [entity_name]}
                }
            }
        }
    }
    response = requests.post(url, json=payload)
    return response.json()

def check_export_eligibility(model_params: int, destination_country: str) -> dict:
    """Check if model export is eligible"""
    restricted_countries = ["KP", "IR", "SY", "CU"]  # Example restricted list
    
    result = {
        "model_params": model_params,
        "destination": destination_country,
        "country_restricted": destination_country in restricted_countries,
        "model_threshold_exceeded": model_params >= 70_000_000_000,
        "export_allowed": destination_country not in restricted_countries
    }
    return result

# Example usage
print(check_sanctions("Example Corp"))
print(check_export_eligibility(70_000_000_000, "CN"))

Watch Out: Pitfall 1: Ignoring the distinction between model parameter count and training compute — export controls are expected to target training FLOPS (e.g., 10^26), not just parameter count, so a small model trained with extreme compute could also be regulated.
Watch Out: Pitfall 2: Assuming open-source licenses override export controls — a model released under Apache 2.0 is still subject to US export regulations if it was trained above the controlled compute threshold.
Watch Out: Pitfall 3: Relying solely on cloud APIs as a backup plan — if you can't run models locally due to regulatory restrictions, cloud providers may also be forced to gatekeep access under the same rules, leaving you with no fallback.
Watch Out: Pitfall 4: Overlooking the Anthropic situation — if Anthropic's model weights are classified or restricted through national security negotiations, the open-weight ecosystem loses one of the most capable model families, reducing competitive pressure on other providers to stay open.
Watch Out: Pitfall 5: Not documenting your model sources — if licensing requirements take effect, you'll need to prove where every model weight file came from and verify it was legally obtained. Poor record-keeping could expose you to liability.

❓ Frequently Asked Questions

Will I still be able to download and run a 70B parameter model locally in 2026?

It depends on where you live and the model's origin. If US export controls are enacted as proposed, models trained above the 10^26 FLOPS threshold would require an export license for international distribution. Within the US, running models locally is unlikely to be criminalized, but acquiring certain model weights from international sources could become restricted. Models trained below the threshold (e.g., many 7B and 14B models) are less likely to be affected.

What's the difference between the Anthropic vs. David Sacks conflict and why does it matter for local AI?

Anthropic has advocated for AI safety through controlled access, supporting frameworks where powerful models are available only through monitored APIs. David Sacks, as a White House AI advisor, has pushed for open and decentralized AI development to prevent a handful of corporations from controlling the entire AI stack. The outcome of this philosophical debate directly determines whether model weights remain publicly downloadable or get locked behind government-approved API gateways.

How do export controls on model weights actually work in practice?

Export controls on AI model weights would work similarly to existing controls on encryption software. The US Bureau of Industry and Security (BIS) would maintain a list of controlled models (based on training compute thresholds). Distributing these weights to foreign nationals — including via public repositories like GitHub or Hugging Face — would require an export license. Penalties for violations can include fines up to $1 million and up to 20 years imprisonment per violation under the Export Control Reform Act.

Can I use quantized versions of controlled models to get around export restrictions?

No. Quantization reduces file size and hardware requirements but does not change the model's training compute or parameter count, which are the metrics expected to be used for export control classification. A quantized 70B model is still a 70B model for regulatory purposes.

What should I do right now to prepare for potential restrictions on open-weight AI?

Three immediate actions: (1) Download and securely archive the model weights you depend on most, (2) build your inference infrastructure to be model-agnostic using OpenAI-compatible API servers like vLLM or TGI, and (3) engage in public comment periods for proposed export control rules to advocate for exemptions that protect open-source AI development.
