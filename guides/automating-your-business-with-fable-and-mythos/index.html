Automating Your Business with Fable and Mythos

This guide explains how Anthropic's Mythos Access transforms static token windows into a dynamic, persistent memory layer for AI agents. It covers the underlying architecture, why it eliminates the forgetting problem, and provides a practical walkthrough to integrate Mythos into your automation workflows.

🎯 Key Takeaways

  • 1Mythos replaces static context windows with a dynamic memory store, dramatically reducing token overhead.
  • 2Persistent memory enables autonomous agents to retain state across hours or days without re‑prompting.
  • 3Only the relevant pieces of state are retrieved on demand, similar to a smart traffic system that adapts in real time.
  • 4Integration is handled via the Anthropic SDK, which abstracts serialization and endpoint communication.
  • 5Enabling Mythos Access requires an Anthropic account and a simple configuration of the agent’s state store.

📋 Prerequisites

  • An active Anthropic account with Mythos Access enabled.
  • Basic familiarity with the Anthropic SDK (Python or Node.js) and how to create/modify agents.

📝 Step-by-Step Guide

1

Step 1: Enable Mythos Access in Your Anthropic Account

Log in to the Anthropic developer portal, navigate to the Mythos Access section, and toggle the feature on. This provisions a dedicated persistent memory endpoint for your account.

2

Step 2: Install and Configure the Anthropic SDK

Add the SDK to your project and set the `state_store` URL provided by Anthropic. The SDK will handle serialization of any JSON‑serializable object you choose to persist.

pip install anthropic-sdk

import anthropic

client = anthropic.Client(api_key="YOUR_API_KEY")
client.state_store = "https://my-mythos-endpoint.anthropic.com/v1/state"
3

Step 3: Define and Persist Agent State

Identify the pieces of information you want to keep across requests (e.g., task progress, user preferences). Use the SDK’s `save_state` and `load_state` helpers to write to and read from the persistent store.

state = {
    "task_id": "order-123",
    "progress": "step_2",
    "user_preferences": {"language": "en", "currency": "USD"}
}
client.save_state(state)

# Later, retrieve the persisted state
restored_state = client.load_state()
print(restored_state["progress"])  # => "step_2"
4

Step 4: Run Your Agent with Persistent Context

When invoking the model, omit the full conversation history. Instead, inject the loaded state into the prompt or system message, allowing the model to continue where it left off.

prompt = f"You are continuing task {restored_state['task_id']}. Current step: {restored_state['progress']}."
response = client.completions.create(
    model="claude-3-sonnet",
    prompt=prompt,
    max_tokens=1024
)
print(response.completion)

💡 Pro Tips

Pro Tip: Cache frequently accessed state locally for sub‑second latency, syncing back to Mythos only on changes.
Pro Tip: Version your persisted objects; include a schema version field to ease future migrations.
Pro Tip: Store only what you need—large blobs inflate token costs when retrieved for prompt construction.

⚠️ Common Pitfalls

Watch Out: Pitfall 1: Forgetting to handle serialization errors. The SDK expects JSON‑serializable data; custom objects must be converted to dicts or strings.
Watch Out: Pitfall 2: Over‑persisting state. Saving the entire conversation each cycle defeats the token‑saving purpose and can hit rate limits.

❓ Frequently Asked Questions

Do I still need to include a prompt context when using Mythos?

Yes, but only the minimal prompt needed for the current reasoning step. The persistent state is injected separately, so you avoid sending the full conversation each call.

What is the latency impact of reading from the Mythos endpoint?

Typical read latency is under 150 ms. For latency‑sensitive workflows, cache the state locally and sync back only when modifications occur.

Can I share the same Mythos state store across multiple agents?

You can, but you should namespace keys (e.g., `agentA/task123`) to avoid collisions and ensure each agent only accesses its own slice of the store.

Is there a size limit on the persisted state?

Mythos enforces a soft limit of 1 MB per stored object. Split large datasets into multiple keyed entries or store bulk data in external storage (e.g., object store) and keep references in Mythos.

How does billing work for Mythos Access?

You are charged based on the number of read/write operations and the total storage used, separate from the per‑token model usage fees.
