📝 Step-by-Step Guide

Step 1: Install Copper and Configure the Prompt Folder

Open the Mac App Store, search for **Copper**, and click **Get** to download the app. Once installed, create a folder named `~/CopperPrompts` (or any location you prefer) where Copper will look for prompt files. In the Copper preferences window, set **Prompt Directory** to this folder and enable the **Auto‑Sync** toggle so changes are reflected instantly in the UI and CLI.

mkdir -p ~/CopperPrompts
open -a "Copper"
# In Copper → Preferences → Prompt Directory, select ~/CopperPrompts and turn on Auto‑Sync
2

Step 2: Add and Version Your Prompts

Create a prompt file in JSON or plain‑text format inside the prompt folder. Copper automatically tracks changes using a hidden git‑style log. To view the history or revert to a previous version, use the `copper revert` command with the log ID shown by `copper log`.

cat > ~/CopperPrompts/generate-api.json <<'EOF'
{
  "system": "You are an expert API designer.",
  "user": "Generate a REST endpoint for {{resource}} with CRUD operations."
}
EOF
copper log          # shows entries with IDs
copper revert --id 42   # rolls back to the version with ID 42
3

Step 3: Invoke Prompts from the CLI

Run a prompt directly from the terminal using the `copper exec` command. Specify the prompt name (derived from the filename) and the target LLM model. The response streams back to the console and can be piped into your editor or build script.

copper exec --prompt generate-api --model gpt-5.5 --var resource=order
# Example output streamed to STDOUT, ready for copy‑paste or redirection
4

Step 4: Insert Prompt Results into Your IDE

With the Copper dashboard open, select a prompt and click the **Insert into IDE** button. Copper uses macOS Services to paste the generated code at the cursor location in supported editors (VS Code, JetBrains, etc.). This eliminates manual copy‑paste steps.

# No CLI needed – just click the button in the Copper UI while your IDE window is focused.
5

Step 5: Automate Batch Prompt Execution (Optional)

For CI pipelines or large batch jobs, write a shell script that loops over a list of prompts and models. Use `copper exec` inside the loop; because Copper runs locally, the overhead is minimal.

#!/bin/bash
PROMPTS=(generate-api fix-bug update-schema)
for P in "${PROMPTS[@]}"; do
  copper exec --prompt $P --model claude-4
  echo "--- $P completed ---"
done

💡 Pro Tips

Pro Tip: Use the hidden `copper log` to audit who changed a prompt and when – useful for team collaboration.
Pro Tip: Map custom keyboard shortcuts (System Preferences → Keyboard → Shortcuts) to `copper exec` for fire‑and‑forget prompt runs.
Pro Tip: Store sensitive variables (API keys, secrets) in macOS Keychain and reference them in prompts via environment variables to keep them out of plain files.

⚠️ Common Pitfalls

Watch Out: Pitfall 1: Forgetting to enable **Auto‑Sync**. Without it, changes made in the folder won’t appear in the Copper UI until you restart the app.
Watch Out: Pitfall 2: Using an unsupported model name (e.g., `gpt5.5` instead of `gpt-5.5`). Copper will return an error; always match the exact model identifier required by the provider.

❓ Frequently Asked Questions

Can Copper manage prompts for multiple LLM providers simultaneously?

Yes. Copper’s `--model` flag accepts any provider‑specific identifier (e.g., `gpt-5.5`, `claude-4`, `gemini-3.5`). Just ensure the corresponding API key is set in your environment.

How does Copper’s version control differ from using Git directly?

Copper stores a lightweight, hidden log that records each prompt edit with an incremental ID, allowing `copper revert` without a full Git repository. This avoids merge conflicts and keeps the workflow self‑contained.

Is it safe to store secret prompts or API keys in the Copper prompt folder?

Prompt files themselves are plain text, so you should keep secrets out of them. Instead, reference environment variables or macOS Keychain entries inside your prompts to maintain security.

Can I use Copper in a CI/CD pipeline?

Absolutely. Because Copper runs locally and has a CLI, you can script batch executions (see Step 5) and incorporate them into your CI jobs without any network latency.

What happens if I invoke a prompt with a model that isn’t installed or authenticated?

Copper will return a clear error indicating the missing provider configuration. Verify that the appropriate API key is exported (e.g., `export OPENAI_API_KEY=…`) before running the command.
