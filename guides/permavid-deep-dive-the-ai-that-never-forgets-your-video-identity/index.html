This guide walks developers through setting up, running, and benchmarking PermaVid’s memory‑augmented diffusion engine. It covers environment preparation, Docker‑based deployment, GPU configuration, and a sample benchmark script that compares PermaVid’s consistency against legacy diffusion tools. The focus is on practical, repeatable steps for VFX artists, editors, and animators who need reliable character and lighting continuity across long video timelines.

📋 Prerequisites

  • A workstation with an NVIDIA GPU that supports CUDA 12+ and 32 GB+ VRAM.
  • Docker Engine (>=20.10) and Docker Compose installed.
  • Python 3.10+ with pip, requests, and csv modules.
  • AWS credentials if you plan to store rendered frames on S3.

Step 1: Clone the PermaVid Repository

Clone the official PermaVid repo from GitHub and navigate into the project directory. This repo contains the diffusion engine, sample scripts, and Docker configuration.

git clone https://github.com/permavid/perma-vid.git
cd perma-vid
2

Step 2: Build the Docker Image

Use the provided Dockerfile to build an image that contains the required CUDA libraries, Python runtime, and the PermaVid codebase. The image will expose a REST endpoint for inference.

docker build -t permavid/perma-vid:latest .
3

Step 3: Configure GPU and Environment Variables

Set environment variables for GPU visibility, API keys, and optional S3 storage. The `CUDA_VISIBLE_DEVICES` variable limits the container to the desired GPU. Use `PERMA_API_KEY` for any internal licensing checks.

export CUDA_VISIBLE_DEVICES=0
export PERMA_API_KEY=YOUR_PERMA_KEY
export AWS_ACCESS_KEY_ID=YOUR_AWS_KEY
export AWS_SECRET_ACCESS_KEY=YOUR_AWS_SECRET
export S3_BUCKET=permavid-render-output

💡 Pro Tips

Pro Tip: Pin the reference photo on the GPU memory using CUDA Unified Memory to reduce latency between frames.
Pro Tip: Use Docker Compose to orchestrate multiple containers: one for PermaVid inference, another for a lightweight FastAPI UI.
Pro Tip: Enable NVIDIA Docker runtime (`--gpus all`) to ensure the container can access the full VRAM.

⚠️ Common Pitfalls

Watch Out: Pitfall 1: Forgetting to set `CUDA_VISIBLE_DEVICES` leads to the container using all GPUs, causing memory contention.
Watch Out: Pitfall 2: Running the benchmark script without a proper baseline tool results in misleading error metrics.

❓ Frequently Asked Questions

What GPU specifications are required for PermaVid?

PermaVid needs a CUDA‑compatible GPU with at least 32 GB of VRAM (e.g., RTX 6000 Ada). Lower‑VRAM GPUs may experience frame drops or memory errors.

Can I run PermaVid inference without Docker?

Yes, but Docker ensures consistent dependencies. If you prefer a native install, clone the repo, create a virtual environment, and install the `requirements.txt` with pip.

How do I integrate PermaVid with an existing video editing workflow?

Expose the inference endpoint via FastAPI, then call it from your editor’s scripting interface (e.g., DaVinci Resolve Fusion or After Effects ExtendScript) to process selected clips.

Is there a licensing cost for PermaVid?

PermaVid is available under a commercial license. Contact sales at sales@permavid.com for pricing details.

What happens if the reference photo is not available during inference?

PermaVid will default to a generic embedding, which can lead to drift. Always provide the pinned reference photo in the request payload.
