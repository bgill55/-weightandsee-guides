Step 1: Audit Against Known-Good Manifest

Generate a hash list of every installed package in your environment and compare it against the official Microsoft AI-Forge manifest. This ensures that no packages have been swapped or modified. You will need to calculate the SHA256 hash for the package metadata or contents and diff them against the trusted list.

cd /path/to/your/venv/lib/pythonX.X/site-packages
sha256sum */*-dist.info/RECORD > local_hashes.txt
diff local_hashes.txt official_ai_forge_hashes.txt
2

Step 2: Scan for Post-Install Hooks

Malicious dependencies often execute scripts immediately after installation. Inspect your package directories for 'postinstall' entry points or suspicious scripts within 'setup.py' files that read environment variables. Look specifically for outbound network requests or file system reads targeting '.env' files.

# Search for postinstall scripts in package metadata
grep -r "postinstall" .

# Search for network requests in suspicious packages like torch-utils-plus
grep -r "requests." ./torch-utils-plus/
3

Step 3: Execute Local Audit Script

Run a custom Python script that recursively walks your 'site-packages' directory. This script flags any package containing a 'postinstall' entry and cross-references it with the official manifest. This ensures that the audit itself does not trigger the malicious code or send data out.

python3 forensic_audit.py --site-packages ./lib/python3.10/site-packages --manifest official_ai_forge_hashes.txt

# Sample script logic
import os
for root, dirs, files in os.walk('./site-packages'):
    if 'postinstall' in files:
        print(f"[!] Suspicious postinstall hook found in: {root}")
4

Step 4: Purge and Rotate

If the audit flags the 'torch-utils-plus' package or any other unauthorized dependencies, immediately remove them using your package manager. Assume that any API keys (e.g., OPENAI_API_KEY) present in environment variables during the installation period are compromised and rotate them immediately in your cloud provider console.

pip uninstall -y torch-utils-plus

# After removal, sanitize environment and rotate keys
unset OPENAI_API_KEY
# Go to your cloud provider's dashboard and regenerate the key

💡 Pro Tips

Pro Tip: Use `pip-audit` or `safety` regularly to check for known vulnerabilities in your dependency tree.
Pro Tip: Pin your dependency versions exactly in `requirements.txt` to prevent accidental installation of malicious updates.
Pro Tip: Monitor egress network traffic from your build machines to detect data exfiltration attempts in real-time.

⚠️ Common Pitfalls

Watch Out: Assuming clean removal: Simply deleting the package folder is insufficient; use the package manager to uninstall to ensure metadata is cleaned.
Watch Out: Incomplete rotation: Rotating the key in the code but forgetting to update the staging/production environment variables leads to service downtime or continued leaks.

❓ Frequently Asked Questions

How do I know if my API keys were stolen?

If the 'torch-utils-plus' package was successfully installed, assume the keys were exfiltrated. Check your cloud provider's usage logs for unauthorized API calls during the timeframe the package was active.

Can I just delete the 'torch-utils-plus' folder?

No, you must use `pip uninstall torch-utils-plus` to properly remove the package and its references. Deleting the folder manually may leave references or trigger errors, and does not address the compromised keys.

Is AI-Forge safe to use now?

You should verify the integrity of your specific installation using the hash manifest method described in Step 1, and ensure you have updated to a patched version of the scaffolding if available.
