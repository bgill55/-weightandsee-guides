Weight and See Open-Source AI Hub

This guide walks through setting up and running the Weight and See Open‑Source AI Hub, covering repository cloning, Docker‑based stack launch, using the unified CLI to invoke agents, and adding new agents via JSON manifests. It also explains the underlying communication patterns with NATS JetStream and Redis service registry, and offers best‑practice tips for contributors.

🎯 Key Takeaways

  • 1The Hub bundles a Docker compose stack that includes model serving, Redis queues, and a Svelte UI, all started with a single `weight‑and‑see launch` command.
  • 2Agents are defined by JSON‑schema manifests and exposed through a unified CLI (`wsee run --agent --input `), enabling instant latency and cost comparisons.
  • 3Inter‑process communication is handled by NATS JetStream, which guarantees at‑least‑once delivery and back‑pressure handling for both CPU‑heavy vision models and GPU‑accelerated LLMs.
  • 4GPU‑bound LLMs run in TensorRT‑optimized containers registered in Redis; the Hub routes requests based on provider capabilities such as batch size and VRAM.
  • 5Adding a new agent is trivial: drop a `manifest.json` into the `agents/` directory, restart the NATS bus, and the CLI can immediately invoke the new tool.

📋 Prerequisites

  • Git and a working terminal
  • Docker Desktop or Docker Engine
  • Go (1.20+) for compiling any Go‑based components
  • Redis server (local or via Docker)
  • NATS server with JetStream enabled

📝 Step-by-Step Guide

1

Step 1: Clone the Hub Repository

Open a terminal and clone the Weight and See repository from GitHub. Navigate into the project directory before running any further commands.

git clone https://github.com/weight-and-see/hub.git
cd hub
2

Step 2: Install Dependencies and Build the CLI

The project uses a Makefile for quick setup. Running `make install` will fetch Go dependencies, build the `weight-and-see` binary, and install it into your `$PATH`.

make install
# Verify installation
weight-and-see --version
3

Step 3: Launch the Docker Compose Stack

Start the full AI stack with Docker Compose. This will spin up containers for model serving, Redis, and the lightweight Svelte UI. The launch script also auto‑discovers available agents via their JSON manifests.

weight-and-see launch
# Or, if you prefer Docker Compose directly:
# docker compose up -d
4

Step 4: Run an Agent via the Unified CLI

Invoke any discovered agent by specifying its name and input file. The CLI publishes a request to the relevant NATS subject and streams real‑time metrics back to the terminal.

wsee run --agent security --input file.pdf
# Example output:
# [INFO] Security scan started
# [METRICS] latency=120ms token_cost=0.02
5

Step 5: Add a Custom Agent

Create a new agent by writing a `manifest.json` in the `agents/` folder. Restart the NATS bus (`weight-and-see restart-bus`) and the CLI will now recognize the new agent without recompiling the core.

// agents/ocr-agent/manifest.json
{
  "name": "ocr",
  "description": "OCR text extraction from images",
  "entry_point": "python ocr.py",
  "parameters": {"image": "string"}
}
# Restart bus
weight-and-see restart-bus
# Test the new agent
wsee run --agent ocr --input image.png

💡 Pro Tips

Pro Tip: Use the `-v` flag with `wsee run` to enable verbose logging and inspect the raw NATS payloads for debugging.
Pro Tip: Leverage the Redis service registry by adding custom provider annotations; this allows the Hub to automatically select the GPU provider with the highest VRAM for heavy LLM workloads.
Pro Tip: When developing new agents, run the GitHub Actions CI locally (`act`) to catch linting and integration test failures before opening a PR.

⚠️ Common Pitfalls

Watch Out: Pitfall 1: Forgetting to restart the NATS bus after adding a new `manifest.json` will result in the CLI not recognizing the agent. Restarting the bus is as simple as `weight-and-see restart-bus`.
Watch Out: Pitfall 2: Using `make install` on a machine without Go 1.20+ will cause compilation errors for the Go‑based core. Ensure your Go version matches the project’s minimum requirement.

❓ Frequently Asked Questions

How do I update the model image used by the Hub?

Edit the `onecli.yaml` file, change the `model` and `image` fields to the desired Docker image, then restart the Docker stack with `weight-and-see launch`.

Can I run the Hub entirely locally without Docker?

The current distribution relies on Docker for container isolation. Running the Go binaries directly would require manually setting up Redis and NATS JetStream, which is not supported by the bundled scripts.

What if my GPU memory is limited and I want to run a large LLM?

You can configure the TensorRT container to use mixed precision (FP16) and set the `batch_size` in the service registry to a smaller value. The Hub will automatically pick the provider with the lowest VRAM usage that still meets the request.

How do I contribute a new benchmark suite?

Add a YAML benchmark definition to the `benchmarks/` directory, run the GitHub Actions workflow locally to verify it, and submit a pull request. The CI will execute the benchmark against all registered agents.
