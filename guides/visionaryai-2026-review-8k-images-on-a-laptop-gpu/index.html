📝 Step-by-Step Guide

1

Step 1: Install the Robotics-Gym Benchmark

Clone the repository and install dependencies to set up the simulated kitchen environment. This suite provides the 'pick-and-place' and object manipulation tasks used for testing.

git clone https://github.com/robotics-gym/benchmark.git
cd benchmark
pip install -r requirements.txt
2

Step 2: Configure Model Inference Pipelines

Load the three models (Mistral, Aurora, Nova) into memory. Ensure your GPU VRAM allocation handles the 8K context window input required for the vision tasks.

python scripts/load_models.py --models mistral-v2 aurora-8b nova-6b --precision fp16
3

Step 3: Run Latency Benchmarks

Execute the instruction generation loop. Measure the time in milliseconds (ms) from input prompt to the generation of the first robot control token. Record averages over 1000 iterations.

python benchmarks/measure_latency.py --iterations 1000 --output latency_results.json
4

Step 4: Measure Sample Efficiency

Train the agents on the specific kitchen task. Record the number of demonstrations required for each model to reach a convergence threshold (e.g., 90% success rate on validation set).

python benchmarks/train_agent.py --model aurora-8b --task kitchen-pluck --max-demos 2500
5

Step 5: Evaluate Real-World Success Rates

Deploy the trained models in the live Robotics-Gym environment. Calculate the percentage of successful task completions (e.g., the 'hummingbird grab') to determine the final reliability score.

python benchmarks/evaluate_success.py --checkpoint best_model.pth --metrics accuracy

💡 Pro Tips

Pro Tip: Use DeepMind Aurora 8B for mission-critical applications where failure is not an option, despite the slightly higher latency.
Pro Tip: Opt for Mistral 7B v2 if you are operating on a tight data budget or require ultra-fast response times.
Pro Tip: Monitor GPU thermals closely during 8K inference, as sustained high-resolution processing can throttle laptop performance.

⚠️ Common Pitfalls

Watch Out: Focusing solely on latency: A fast model (like Nova) that fails frequently (88% success) increases total operational time due to retries.
Watch Out: Ignoring sample efficiency: Models requiring more demonstrations (like Nova) significantly increase the cost and time of data labeling.
Watch Out: Hardware bottlenecks: Ensure your laptop's memory bandwidth is sufficient for 8K image feeds, otherwise, latency metrics will be skewed by I/O operations.
