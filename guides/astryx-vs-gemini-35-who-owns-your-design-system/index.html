Astryx vs. Gemini 3.5: Who Owns Your Design System?

This deep dive explores Meta's release of Astryx, an open-protocol framework designed to solve the issue of AI 'hallucination' in UI generation by enforcing strict design system constraints via JSON schemas. It contrasts Astryx's transparent, locally executable architecture with the proprietary, cloud-based 'black box' approaches of competitors like Google's Gemini 3.5. 🔬 Key Findings

JSON Schema Enforcement Prevents Hallucinations

Astryx modifies the AI input pipeline by converting design tokens (colors, spacing, typography) into a structured JSON schema. The coding agent must ingest these constraints before generating code, and schema validation immediately rejects any output that deviates from the defined values, effectively treating CSS as a strict set of constraints rather than a creative exercise.

Open-Protocol vs. Proprietary Walled Gardens

Unlike Google's Gemini 3.5, which requires users to upload assets to a cloud-based black box that analyzes flattened raster images, Astryx runs locally. This allows developers to inspect exactly how their design system is mapped to the model's context window, providing debugging capabilities that closed-source systems actively prevent.

Model Agnosticism and Vendor Lock-in Removal

Astryx decouples the design token format from the specific AI model provider. Developers can route Astryx tokens to Llama 4, Claude 4, or local models without changing their frontend workflow, ensuring the design system remains the source of truth regardless of API pricing changes or model updates.

Automated CI/CD Quality Assurance

The framework integrates into CI pipelines to act as an automated gatekeeper. It can be configured to flag or reject commits that introduce 'magic numbers' or hard-coded color values, shifting the burden of design consistency from manual code review to an automated enforcement layer.

⚙️ Technical Background

Current AI coding agents often treat CSS generation as a probabilistic task, leading to outputs that ignore specific design tokens and semantic relationships. Astryx addresses this by acting as a middleware bridge between design files (e.g., Figma exports) and the code repository. It translates visual primitives into structured data (JSON) that the LLM uses as a rigid reference point. By running this interpretation layer locally, Astryx validates the model's output against the original design tokens, ensuring that concepts like 'medium spacing' are rendered as exact pixel values (e.g., 8px) rather than approximations.

💭 Expert Analysis

Astryx represents a maturation in the AI-augmented development workflow, moving from simple code generation to structured, constraint-based generation. The architectural decision to separate the design interpretation protocol from the model itself is a strong counter to current vendor lock-in trends. However, the system's ultimate success depends on the willingness of major model providers (beyond Meta) to effectively adhere to these external schemas, as well as the ease of integrating the middleware bridge into complex legacy CI/CD environments.

❓ Frequently Asked Questions

How does Astryx ensure AI doesn't guess CSS values?

Astryx converts design tokens into a structured JSON schema that the model ingests before writing code. Schema validation then rejects any output that does not match the strict constraints defined in that schema.

Can I use Astryx with models other than Llama 4?

Yes, Astryx is designed to be model-agnostic, allowing you to route tokens to Claude 4, local models, or other engines without changing your frontend workflow.

Why is Astryx considered better than Google's approach for design systems?

Astryx runs locally and exposes the interpretation layer, allowing for debugging and data privacy. In contrast, Google's Gemini 3.5 requires uploading assets to a proprietary cloud 'black box' that analyzes flattened images rather than underlying data structures.

How does Astryx integrate with the development workflow?

It runs as a middleware bridge between Figma exports and the Git repository, automatically translating design changes into code diffs and integrating with CI pipelines to flag design inconsistencies.
