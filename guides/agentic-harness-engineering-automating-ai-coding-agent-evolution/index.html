Agentic Harness Engineering: Automating AI Coding Agent Evolution

📝 Step-by-Step Guide

1

Step 1: Clone the AHE repository and build the Docker image

Open a terminal, clone the official AHE repo, and build the reproducible Docker image. The Dockerfile installs Python, Rust, the genetic‑algorithm optimizer, and the SQLite runtime. Building the image once ensures identical environments across runs and machines.

git clone https://github.com/agentic-harness-engineering/ahe.git
cd ahe
docker build -t ahe:evolver .
2

Step 2: Launch the evolution pipeline in a deterministic container

Run the evolution container with GPU access, mounting the repository workspace so that generated harness candidates are persisted. The command spins up eight parallel workers that each evaluate 20 Terminal‑Bench queries, logging results to `observability.db`. Use the `--seed` flag for reproducibility and `--workers 8` to match the paper’s configuration.

docker run \
  --gpus all \
  --rm \
  -v $(pwd):/workspace \
  -e SEED=42 \
  ahe:evolver \
  python evolve.py \
    --bench terminal_bench \
    --model gpt5p5 \
    --workers 8 \
    --generations 50 \
    --output_dir /workspace/evolution_output
3

Step 3: Extract the best harness and test it on a new model

When the evolution finishes, the optimizer writes the highest‑fitness harness to `best_harness.py`. You can immediately reuse it with any supported model; the framework rewrites model‑specific API calls on the fly. Run the inference script with the new model flag and verify that pass@1 stays at ~77 %.

# Run on Llama‑4
python run_agent.py \
  --model llama4 \
  --harness evolution_output/best_harness.py

# Optional sanity check on another model
python run_agent.py \
  --model deepseekv4 \
  --harness evolution_output/best_harness.py
4

Step 4: Register the frozen harness and add a CI quality gate

Push the frozen harness to the model‑agnostic registry (a simple Git‑LFS backed bucket in this example). Then add a step to your CI pipeline that pulls the latest harness, evaluates it on Terminal‑Bench, and fails the build if pass@1 drops below 70 %. This guarantees that every code change maintains or improves generation quality.

# Register the harness
git add evolution_output/best_harness.py
git commit -m "Register evolved harness v1.0"
git push origin main

# CI snippet (GitHub Actions example)
steps:
  - name: Checkout repo
    uses: actions/checkout@v3
  - name: Pull harness
    run: git pull origin main
  - name: Evaluate harness
    run: |
      python evaluate.py \
        --bench terminal_bench \
        --harness evolution_output/best_harness.py \
        --threshold 0.70
      if [ $? -ne 0 ]; then exit 1; fi

💡 Pro Tips

Pro Tip: Set `SEED` (e.g., `-e SEED=1234`) for deterministic evolution; you can replay any generation by re‑running the container with the same seed.
Pro Tip: Tune the mutation probability (`--mut_rate`) if you see premature convergence; a typical range is 0.05–0.15.
Pro Tip: Monitor `observability.db` with the provided `sqlite3` CLI to inspect token‑level latency trends and spot bottlenecks early.

⚠️ Common Pitfalls

Watch Out: Pitfall 1: Exceeding GPU memory – launching more than 8 workers on a 12 GB card will cause OOM. Keep `--workers` at 8 or lower unless you increase batch size.
Watch Out: Pitfall 2: Forgetting to mount the workspace volume – without `-v $(pwd):/workspace` the generated harness files disappear when the container exits.

❓ Frequently Asked Questions

Do I need to edit the harness code when switching to a new model?

No. After evolution finishes, AHE automatically rewrites model‑specific API calls when you invoke `run_agent.py --model --harness best_harness.py`.

How long does a full 50‑generation evolution run on an RTX 4090?

On a single RTX 4090 with eight parallel workers, a typical 50‑generation run completes in 4–6 hours, depending on benchmark size.

Can I run AHE without a GPU?

Technically yes, but the genetic optimizer and benchmark evaluations are GPU‑heavy; running on CPU will be >10× slower and may exhaust memory.

How do I make the evolution reproducible across machines?

Pass a fixed seed via `-e SEED=` to the Docker container and keep the Docker image version pinned (`ahe:evolver`). The same seed guarantees identical candidate generation and fitness evaluation.

What if the CI quality gate fails after a minor code change?

Investigate the `observability.db` for latency spikes or token‑count regressions, then either revert the change or run a short local evolution (`--generations 10`) to adapt the harness.
