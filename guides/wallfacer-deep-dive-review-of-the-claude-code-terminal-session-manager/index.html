🔬 Key Findings

Unified Keystroke + AI Suggestion Recording

Wallfacer captures every stdin/stdout event **and** the JSON payload returned by Claude Code’s suggestion API, embedding a suggestion‑ID tag alongside each terminal line. This creates a single `.wf` file that represents both the raw terminal activity and the AI‑generated assistance.

Character‑Level Diff Produces Smaller Bundles

The built‑in `wallfacer diff` command isolates only the characters that changed between two sessions and strips redundant escape sequences. In the side‑by‑side benchmark Wallfacer’s diff bundles were up to 40 % smaller than those produced by Asciinema or TTYRec.

Low Runtime Overhead

During high‑throughput Go test runs, Wallfacer kept CPU usage below 5 % on an RTX 4090 system, whereas Asciinema spiked to roughly 12 % under the same conditions. The lightweight daemon design means long recordings do not throttle the host machine.

AI‑Assisted Playback Synchronizes Suggestion Timing

When replaying a `.wf` file, Wallfacer injects Claude Code suggestions at the exact timestamps they were originally offered, yielding smoother playback and a more faithful reconstruction of the developer’s decision‑making process.

Seamless CI Integration and Artifact Management

Because a `.wf` file is plain data, it can be stored in artifact repositories, version‑controlled with Git, and replayed in CI pipelines to provide reproducible build‑step recordings with AI‑augmented context.

⚙️ Technical Background

Terminal session recorders capture the stream of characters sent to and from a shell, typically by intercepting PTY I/O. Traditional tools (e.g., Asciinema, TTYRec) store raw byte streams, which include escape sequences for coloring and cursor movement. Wallfacer augments this model by also tapping the Claude Code REST API, persisting each suggestion’s JSON payload alongside the terminal output, and then post‑processing the stream to remove redundant escapes while preserving AI‑interaction metadata.

💭 Expert Analysis

Wallfacer’s integration of AI suggestion metadata directly into terminal recordings is a notable advancement, closing the feedback loop between human actions and model outputs. The benchmark shows credible performance gains, though the CPU savings are hardware‑dependent and may narrow on less powerful CPUs. The approach also raises questions about privacy—while raw code stays local, suggestion IDs are still sent to Anthropic’s servers unless explicitly opted out. Overall, Wallfacer is a promising prototype for AI‑augmented developer tooling, but broader adoption will depend on ecosystem support and clear privacy controls.

❓ Frequently Asked Questions

How do I install Wallfacer?

Clone the Claude Code repo and run `pip install .` (or `cargo install wallfacer` if a Rust binary is provided). Then ensure the `wallfacer` executable is on your PATH.

Can Wallfacer be used without sending data to Claude’s servers?

Yes. By default only suggestion IDs are logged; you can disable all network calls with the `--offline` flag, which records terminal I/O without any AI payload.

What format is the `.wf` file and can I parse it manually?

A `.wf` file is a JSON‑L (line‑delimited JSON) archive where each line contains a terminal event object and an optional `suggestion` field. You can stream‑parse it with any JSON library.

Is the diff output compatible with standard `git diff` tools?

`wallfacer diff` produces its own coloured diff view, but you can export the changes to a plain‑text diff using the `--output=patch` flag, which can be applied with `git apply`.

How does Wallfacer affect CI job runtime?

The recorder adds <5 % CPU overhead and negligible I/O, so CI jobs typically see less than a second increase in total runtime, while gaining full reproducibility of build steps.
