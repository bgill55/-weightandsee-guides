AgentHQ: Revolutionizing Multi-Agent Orchestration with an Interactive Office Theme

This guide walks you through setting up AgentHQ – a no‑code, visual AI‑agent orchestration platform that turns multi‑agent pipelines into an interactive office layout. You’ll clone the repository, configure agents and connectors, run the platform locally, export the flow as production‑ready Docker/Helm artifacts, and integrate the generated SDK code into your CI pipeline.

🎯 Key Takeaways

  • 1AgentHQ’s drag‑and‑drop UI eliminates boilerplate YAML/chain code while preserving full configurability of each agent.
  • 2The backend uses a Node.js server with a WebSocket + NATS event bus, delivering sub‑millisecond coordination latency.
  • 3Real‑time monitoring panels expose token usage, API latency, and tool‑call payloads for instant debugging.
  • 4Flows can be exported as JSON, Docker Compose, or Helm charts, enabling seamless CI/CD and Kubernetes deployments.
  • 5Secrets are stored in an encrypted vault and accessed via secure RPC, keeping API keys out of the front‑end.
  • 6Built‑in connectors (HTTP, PostgreSQL, file system) and retry nodes simplify error handling and reliability.

📋 Prerequisites

  • Node.js (v18 or later) and npm installed locally.
  • Docker (and optionally a Kubernetes cluster with Helm) for production deployment.

📝 Step-by-Step Guide

1

Step 1: Clone the AgentHQ repository and install dependencies

Open a terminal, clone the official repo, navigate into the directory, and install all Node.js packages. The project bundles the React front‑end, Phaser‑based canvas, and the backend server in one monorepo. ```bash # Clone the repo (choose either official or tools‑for‑agents fork) git clone https://github.com/nordinit/agent-hq.git # or # git clone https://github.com/tools-for-agents/agent-hq.git cd agent-hq # Install server and client dependencies npm ci # Verify the installation by building the UI npm run build ```

git clone https://github.com/nordinit/agent-hq.git
cd agent-hq
npm ci
npm run build
2

Step 2: Configure environment variables and start the development server

Create a `.env` file at the project root with your AI provider keys and NATS connection string. The UI reads these values at runtime and the backend uses them for agent SDK sessions. ```dotenv # .env OPENAI_API_KEY=sk-**************** CLAUDE_API_KEY=sk-**************** NATS_URL=nats://localhost:4222 VAULT_KEY=super-secret-256-bit-key ``` Then launch the combined server which serves the React app and opens a WebSocket on port 3000. ```bash npm run dev ``` Visit `http://localhost:3000` in your browser – you should see the empty office floor ready for drag‑and‑drop.

OPENAI_API_KEY=sk-...
CLAUDE_API_KEY=sk-...
NATS_URL=nats://localhost:4222
VAULT_KEY=super-secret-256-bit-key

npm run dev
3

Step 3: Build a ticket‑routing workflow in the UI

In the browser UI: 1. Drag a **Ticket Ingest** agent onto the floor. 2. Open its **Tool Config** tab, set the webhook URL (e.g., `https://myapp.com/webhook`) and HTTP method `POST`. 3. Drag a **Classifier** agent, select **OpenAI GPT‑5.5** from the role dropdown, set `temperature: 0` and `max_tokens: 512`. 4. Connect the two agents with a straight line for sequential execution. 5. Drag a **Responder** agent, open its Tool Config, select **Slack** connector, paste your Slack webhook, and map the response variable `status` from the classifier to the message payload. 6. Add a **Retry** node after the Classifier with `maxAttempts: 3` and exponential back‑off. 7. Click the green **Deploy** button – AgentHQ will compile the graph into a JSON definition and generate a runnable Node.js script. The generated script lives in `./exported/flow.js` and looks like:

const { AgentHQ } = require('@agenthq/sdk');

async function main() {
  const flow = await AgentHQ.loadFlow('./exported/flow.json');
  await flow.run();
}

main().catch(console.error);
4

Step 4: Export the flow as Docker Compose and spin it up locally

From the UI, click **Export → Docker Compose**. AgentHQ creates a `docker-compose.yml` that defines each agent as a separate service, a NATS container, and a vault container. ```bash # Pull the generated compose file into the repo root cp ./exported/docker-compose.yml . # Start all services docker compose up -d ``` Verify the containers are running: ```bash docker compose ps ``` You can now hit the same `http://localhost:3000` UI – the backend is now running inside Docker, ready for production‑like testing.

docker compose up -d

docker compose ps
5

Step 5: Deploy to Kubernetes with the provided Helm chart

AgentHQ ships a Helm chart under `charts/agenthq`. Update `values.yaml` with your secret keys (or reference a Kubernetes secret) and install the chart into your cluster. ```bash # Package the chart (optional) helm package charts/agenthq # Install/upgrade the release helm upgrade --install agenthq ./agenthq -n ai-orchestration --create-namespace \ --set openai.apiKey=$OPENAI_API_KEY \ --set claude.apiKey=$CLAUDE_API_KEY \ --set nats.url=nats://nats:4222 ``` The chart creates a Deployment for the Node.js server, a StatefulSet for NATS, and a ConfigMap with the exported flow JSON. After the Helm release is ready, forward the UI port and test: ```bash kubectl port-forward svc/agenthq-ui 3000:80 -n ai-orchestration ``` Now `http://localhost:3000` points to the Kubernetes‑hosted instance.

helm upgrade --install agenthq ./agenthq -n ai-orchestration --create-namespace \
  --set openai.apiKey=$OPENAI_API_KEY \
  --set claude.apiKey=$CLAUDE_API_KEY \
  --set nats.url=nats://nats:4222

kubectl port-forward svc/agenthq-ui 3000:80 -n ai-orchestration

💡 Pro Tips

Pro Tip: Version‑control your exported JSON flow – commit it to Git and use pull‑requests to review changes to the orchestration graph.
Pro Tip: Leverage the built‑in **Retry** node for any external API calls; set a back‑off strategy to avoid hammering rate‑limited services.
Pro Tip: Store API keys exclusively in the vault UI; never hard‑code them in the exported script or Docker Compose files.
Pro Tip: When scaling on Kubernetes, enable the Helm chart’s `autoScaling.enabled` flag to let the Horizontal Pod Autoscaler react to CPU or custom token‑usage metrics.
Pro Tip: Use the real‑time monitoring panel to spot token spikes early – adjust `max_tokens` or temperature directly from the side panel and redeploy instantly.

⚠️ Common Pitfalls

Watch Out: Pitfall 1: Forgetting to set the `VAULT_KEY` environment variable – the server will start but all secret fetches return empty, causing API authentication failures.
Watch Out: Pitfall 2: Mis‑matching JSONPath expressions in tool connectors – the downstream agent receives `undefined`, leading to silent failures that only appear in the log badge.
Watch Out: Pitfall 3: Running NATS on the default port locally while another service occupies it – the backend will crash with a connection error; change `NATS_URL` to an unused port.
Watch Out: Pitfall 4: Exporting a flow before all agents are saved – the generated Docker Compose may reference non‑existent services, causing container startup failures.

❓ Frequently Asked Questions

Can I add a custom tool or API endpoint that isn’t built‑in?

Yes. In the **Tool Config** tab you can define a new HTTP connector by specifying the endpoint URL, HTTP method, headers, and a JSONPath mapping for the response. After saving, the tool appears as a node you can connect to any agent.

How do I integrate the exported flow into my existing CI/CD pipeline?

After clicking **Deploy**, AgentHQ generates a Node.js script that imports `@agenthq/sdk`. Add this script to your repo, run `npm install @agenthq/sdk` in your CI environment, and execute the script as part of your build step (e.g., `node ./exported/flow.js`).

What’s the best way to manage API secrets for production?

Store secrets in the built‑in vault UI; the vault encrypts them with the `VAULT_KEY`. In production (Docker/K8s) you can mount the vault secret as an environment variable or use a Kubernetes secret referenced by the Helm chart’s `vault.secretName` value.

Can I run AgentHQ on a cloud VM without Docker?

Absolutely. After installing Node.js, set the required environment variables and run `npm run start` (or `npm run prod`). The server will serve both the React UI and the WebSocket on the same port, suitable for a single‑VM deployment.

How does AgentHQ handle failed tool calls?

Attach a **Retry** node to any agent. You can configure `maxAttempts`, `backoffStrategy` (fixed or exponential), and a fallback node that logs the error. Failed calls are visualized with a red badge on the agent’s desk and a detailed log view.
