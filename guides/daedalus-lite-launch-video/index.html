Step 2: Launch the REPL inside your TypeScript project

Navigate to the root of your TypeScript project (the folder containing `tsconfig.json`). Run the Daedalus‑Lite binary. The REPL will start instantly, load the TypeScript configuration, and expose your project modules. - `cd` into the project directory. - Start the REPL with `daedalus-lite` or `npx daedalus-lite` if you prefer a local install. - Observe the prompt (`>`) indicating readiness.

Step 3: Import and execute TypeScript code on the fly

Within the REPL you can import any `.ts` file using standard ES‑module syntax. The REPL compiles the file in‑memory, preserving type safety. After importing, call exported functions and view results instantly. - Use the `import` statement to bring in a module. - Call a function and see the output. - Errors are displayed with native Node stack traces.

Step 4: Use built‑in scaffolding commands to generate boilerplate

Daedalus‑Lite ships with a colon‑prefixed command system. For example, `:scaffold component MyComponent` creates a new React component file based on a preset template. The generated files are placed in your project structure, ready for immediate use. - Type the scaffold command. - Confirm the generated files appear in the file explorer. - Continue editing or run the REPL again to import the new component.

Step 5: Exit the REPL while preserving history

When you’re done, exit with `Ctrl+D` or type `.exit`. Daedalus‑Lite saves the command history to a hidden file (`.daedalus_history`) in your project root, allowing you to recall previous commands with the up‑arrow key on the next launch. - Press `Ctrl+D` or type `.exit`. - Relaunch the REPL and press the up‑arrow to see previous commands. 

.exit
# On next launch
up-arrow  // shows previous commands

⚠️ Common Pitfalls

Watch Out: Pitfall 1: Running the REPL outside a folder with a `tsconfig.json` causes type‑checking to fall back to default settings. Always launch from the project root.
Watch Out: Pitfall 2: Installing Daedalus‑Lite locally without adding it to `package.json` can lead to version mismatches across team members. Prefer a global install or add it as a devDependency (`npm i -D daedalus-lite`).

❓ Frequently Asked Questions

Do I need to install any dependencies for Daedalus‑Lite to work?

No. Daedalus‑Lite is zero‑dependency; only Node.js (v14+) and npm are required.

Can I use Daedalus‑Lite with a monorepo that has multiple tsconfig files?

Yes. Start the REPL inside the specific package folder; it will read the nearest `tsconfig.json`. You can also pass a config path with `--config ./path/tsconfig.json`.

How do I create my own plugin for Daedalus‑Lite?

Write a Node module that exports a function accepting the REPL instance. Then install it via `npm i ` and load it with `:plugin install `.

What happens to my session history if I delete the `.daedalus_history` file?

The REPL will start with an empty history. The file is recreated on exit, so you can safely back it up if you want to preserve past commands.

Is there a way to run Daedalus‑Lite without installing it globally?

Yes. Add it as a devDependency (`npm i -D daedalus-lite`) and run it with `npx daedalus-lite` from the project root.
