Step 1: Define the Graph-Based Representation

Instead of predicting 3D coordinates directly, structure your data model to represent the CAD build history as a directed acyclic graph (DAG). Each node in the graph represents a distinct operation (e.g., Sketch, Extrude, Fillet), and edges represent dependencies. This allows the model to generate a sequence of tokens that define these operations and their relationships.

class OperationNode:
    def __init__(self, op_type, parent_id=None, parameters=None):
        self.op_type = op_type  # e.g., 'sketch', 'extrude'
        self.parent_id = parent_id # Dependency link
        self.parameters = parameters # Dimensions, constraints

class CADGraph:
    def __init__(self):
        self.nodes = []
        self.root = OperationNode('origin')

    def add_operation(self, op_type, parent_id, params):
        new_node = OperationNode(op_type, parent_id, params)
        self.nodes.append(new_node)
        return new_node

Step 2: Implement Constrained Decoding Logic

Integrate a grammar-based validator into the token generation loop. This function must check the current state of the graph to ensure the next token is valid. For example, an 'Extrude' operation is grammatically invalid if the previous node was not a 'Sketch' or a planar face.

def is_valid_transition(graph, current_node_type, next_token):
    # Define grammar rules
    valid_transitions = {
        'sketch': ['extrude', 'revolve', 'cut'],
        'extrude': ['fillet', 'chamfer', 'boolean_union'],
        'origin': ['sketch']
    }
    
    if current_node_type in valid_transitions:
        return next_token in valid_transitions[current_node_type]
    return False

# Usage during generation loop
if is_valid_transition(graph, last_node.op_type, predicted_token):

Step 3: Configure Real-Time Geometric Validation

Set up a geometry kernel to validate the physical result of the proposed operation before committing it to the graph. If the decoder proposes an extrusion that results in a self-intersecting mesh or breaks manifoldness (e.g., creating a hole with zero thickness), the decoder must reject the token and sample a new one.

import OCC.Core.BRepCheck as BRepCheck

def validate_geometry(brep_object):
    checker = BRepCheck.BRepCheck_Analyzer(brep_object)
    # Returns True if the shape is valid (manifold, closed)
    is_valid = checker.IsValid() 
    
    if not is_valid:
        print("Invalid geometry detected: Rejected by decoder.")
        return False
    return True

# Inside the generation step
proposed_shape = kernel.apply_operation(graph, new_node)
if validate_geometry(proposed_shape):
    graph.commit(new_node)

Step 4: Export Graph to Manufacturable STEP File

Once the sequence of operations is generated and validated, traverse the final graph to reconstruct the solid body using the CAD kernel. Export this body as a STEP (Standard for the Exchange of Product Data) file. This ensures the output retains the construction tree and is compatible with industrial CAM/CAE software.

from OCC.Core.STEPControl import STEPControl_Writer
from OCC.Core.IFSelect import IFSelect_RetDone, IFSelect_ItemsByEntity

def export_step(graph_shape, filename="output.step"):
    step_writer = STEPControl_Writer()
    step_writer.Transfer(graph_shape, STEPControl_AsIs)
    
    status = step_writer.Write(filename)
    if status == IFSelect_RetDone:
        print(f"Successfully exported {filename}")
    else:
        print("Failed to export STEP file.")

💡 Pro Tips

Pro Tip: Cache intermediate geometric states during graph traversal to speed up the real-time validation process.
Pro Tip: Use a separate, lightweight B-Rep checker for the initial grammar pass before running the full kernel validation to optimize inference speed.
Pro Tip: When defining the token vocabulary, include explicit parameter tokens (e.g., 'distance=10mm') rather than just continuous values to make constrained decoding more robust.

⚠️ Common Pitfalls

Watch Out: Circular Dependencies: Creating a graph where a child node references a parent that hasn't been finalized yet, causing the geometry kernel to crash.
Watch Out: Ignoring Tolerance: Failing to set appropriate geometric modeling tolerances can lead to 'valid' shapes that fail in downstream manufacturing software.
Watch Out: Over-constraining: Making the grammar too strict can prevent the model from generating complex, valid organic shapes that break standard rules.

❓ Frequently Asked Questions

Why use a graph-based representation instead of point clouds?

Graph-based representations capture the construction history and logical dependencies between features (e.g., a fillet depends on an edge), which is necessary for generating editable, parametric CAD files rather than static visual meshes.

What happens if the decoder generates an invalid operation?

The constrained decoding logic identifies the violation based on the predefined grammar or geometric check, rejects the token, and forces the model to sample the next best token until a valid operation is proposed.

Can CADDY generate assemblies or only single parts?

The architecture is designed for single-part generation via a construction graph. Generating assemblies would require an additional hierarchy layer to manage part relationships and mating conditions.
