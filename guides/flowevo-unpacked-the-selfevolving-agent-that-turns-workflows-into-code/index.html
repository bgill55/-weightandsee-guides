🎯 Key Takeaways

  • 1FlowEvo compiles verified workflow traces into reusable Python skill objects at inference time.
  • 2The skill bank persists compiled skills for instant reuse across sessions.
  • 3Token consumption can be reduced by up to a third while maintaining or improving task success rates.
  • 4Skill compilation is controlled by a confidence threshold and can be toggled via CLI flags.

📋 Prerequisites

  • Python 3.9 or later
  • Access to the ChatGPT 5 point 5 API (or compatible LLM endpoint)
  • Docker (optional for containerized setup)

📝 Step-by-Step Guide

1

Step 1: Install FlowEvo and dependencies

Install the FlowEvo Python package and required libraries using pip, then pull the official Docker image if you prefer container isolation.

pip install flowevo
# Optional: docker pull defenseseu/flowevo:latest
2

Step 2: Enable skill compilation and configure the threshold

Add the --enable-skill-compilation flag to your runtime command and optionally set a custom compilation threshold to control how aggressively traces are compiled into skills.

python run_flow.py --agent flow_evo --task generate_report --enable-skill-compilation --compilation-threshold 0.85
3

Step 3: Run a sample workflow and observe skill creation

Execute a task that involves reading a CSV, computing aggregates, and writing a PDF. FlowEvo will log the trace, compile it into a Python function, and store it in the skill bank.

from flow_evo import Agent
agent = Agent(model="gpt-5-point-5", skill_compilation=True)
result = agent.run(task="generate_report", inputs={"csv_path":"data/sales.csv"})
print(result)
4

Step 4: Retrieve and reuse a compiled skill

When the same task is invoked again, FlowEvo loads the compiled function from the skill bank, bypassing the LLM for deterministic sub‑steps and dramatically reducing token usage.

# Subsequent run automatically reuses the compiled skill
result2 = agent.run(task="generate_report", inputs={"csv_path":"data/sales.csv"})

💡 Pro Tips

Pro Tip: Set a higher compilation‑threshold for stricter skill validation, which reduces the chance of runtime errors but may miss some optimizations.
Pro Tip: Version‑control the skills/ directory to track changes in compiled functions and enable collaborative sharing across team members.
Pro Tip: Profile token usage with the built‑in telemetry flag (--telemetry true) to quantify savings before deploying to production.

⚠️ Common Pitfalls

Watch Out: Failing to add the --enable-skill-compilation flag will cause the compiler to be bypassed, resulting in no token savings.
Watch Out: Overriding the default confidence threshold without testing can lead to premature compilation of low‑confidence traces, causing incorrect outputs.
Watch Out: Neglecting to add type hints or input validation to compiled functions may cause runtime type errors when reused with different data shapes.

❓ Frequently Asked Questions

Do I need an API key to use FlowEvo?

Yes. FlowEvo requires access to a compatible LLM endpoint such as the ChatGPT 5 point 5 API; provide the key via the FLOW_EVO_API_KEY environment variable.

Can compiled skills be shared across different machines?

Skills are stored as Python files in the skills/ directory; they can be committed to version control and loaded on any machine with the same codebase and dependencies.

What happens if a compiled skill raises an exception?

FlowEvo falls back to the raw LLM path, logs a warning, and records the failure for future analysis; you can then manually edit or discard the faulty skill.
