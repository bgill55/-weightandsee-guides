⚠️ Common Pitfalls

Watch Out: Pitfall 1: Forcing a 175B-parameter multimodal model into a narrow spatial task. This results in 45s inference latency and 89% accuracy, making it clinically unusable compared to a 0.2s, 96% accurate CNN.
Watch Out: Pitfall 2: Ignoring the spatial relationship loss in transformers. Treating a 1024x1024 CT scan as 256,000 flat tokens destroys the geometric context needed to identify tumor boundaries.
Watch Out: Pitfall 3: Hitting Exa API rate limits. Using the free tier of the Exa MCP integration without an API key will block your agent's web search capabilities during high-volume research phases.

❓ Frequently Asked Questions

Why does a 10-year-old CNN outperform a 1.7T-parameter multimodal model in medical imaging?

CNNs use hierarchical convolutional layers that naturally preserve spatial relationships (edges, shapes, textures), which is critical for detecting tumors. Transformers treat images as flat sequences of patches, losing spatial context and resulting in lower accuracy (89% vs 96%) and higher latency (45s vs 0.2s).

How can we implement the Exa MCP integration to bypass rate limits?

Generate an API key at dashboard.exa.ai/api-keys and update the MCP server URL to include the key: `https://mcp.exa.ai/mcp?exaApiKey=YOUR_EXA_API_KEY`. This grants unlimited web search access for your AI agents.

Is it safe to deploy open-weight CNNs on-premise for medical data?

Yes, deploying open-weight CNNs on-premise is highly recommended for medical data. It ensures strict data sovereignty, complies with HIPAA/GDPR regulations, and eliminates cloud per-API-call fees, resulting in an 80% cost reduction.

When should we still use a massive general-purpose LLM instead of a CNN?

Use massive general-purpose LLMs for broad reasoning tasks, such as summarizing clinical notes, interpreting complex patient histories, or multi-step logical deduction. For narrow, spatial recognition tasks like tumor detection, always default to a domain-optimized CNN.
