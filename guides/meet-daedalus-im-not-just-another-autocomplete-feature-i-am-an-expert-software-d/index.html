Step 1: Launch Daedalus and verify the router is running

Start Daedalus in your terminal. Upon launch, the router initializes and begins running health checks every 30 seconds. You should see a confirmation message: '[OK] Router started. Health checks running every 30s.' The prompt will show 'o>?' indicating Daedalus is ready for commands. Tab completion is available for all commands — type '?' to see the full command list at any time.

# Launch Daedalus in your terminal
$ daedalus

# Expected output:
# Type ? for commands - Tab completes - Be nice to your AI
# [OK] Router started. Health checks running every 30s.
# o>?
2

Step 2: Manage your active file context

Before asking Daedalus to work on your code, you need to tell it which files to focus on. Use /add to load specific files into the active context so Daedalus builds a mental model of their structure, dependencies, and purpose. Use /remove to drop files that are no longer relevant, and /context at any time to see what is currently loaded. This explicit context management is what separates Daedalus from generic autocomplete — it only suggests changes based on the files you have loaded.

# Add a file to active context
> /add src/database/queries.py

# Add another file
> /add src/api/routes.py

# View currently loaded context
> /context
# Output shows all files currently in context

# Remove a file from context
> /remove src/database/queries.py

# Paste clipboard content (text or image) as a message
> /paste
3

Step 3: Index your codebase and navigate symbols

For non-trivial projects, start by running /index to build a searchable FTS5 symbol index of your entire codebase. This enables powerful navigation commands: /find to search for symbols by name, /def to jump to a symbol's definition, and /refs to map every place a variable, function, or method is referenced. This is essential for understanding large codebases before making changes.

# Build the symbol index for your codebase
> /index
# [TOOL] Indexing codebase... (this may take a moment for large projects)

# Search for a symbol
> /find UserService

# Get the definition of a symbol
> /def get_references

# Find all references to a symbol
> /refs process_payment
4

Step 4: Configure your profile, style, and project settings

Customize Daedalus to match your preferences and project conventions. Use /profile to set your user profile, /style to define coding style preferences (comment verbosity, indentation, paradigm preferences), and /project to view or set project-level configuration that adapts Daedalus to your codebase's specific conventions. Use /extract to manually pull facts from your session — this is how you teach Daedalus tribal knowledge like architectural decisions, naming conventions, or business logic that isn't obvious from the code.

# Set your coding style preferences
> /style
# Follow the prompts to configure:
#   - Comment verbosity: concise / verbose
#   - Indentation: tabs / spaces
#   - Paradigm: functional / object-oriented

# View or set project-level configuration
> /project

# Extract a fact from the current session
> /extract "We use UUIDs for all primary keys"
# Daedalus stores this fact for future reference
5

Step 5: Audit, commit, and iterate with Daedalus

Ask Daedalus to perform high-level tasks like auditing your codebase. When you ask for an audit, Daedalus will ask clarifying questions about your priorities (performance, readability, security, test coverage) rather than dumping generic suggestions. Once you agree on changes, use /commit to stage and commit them, or /undo to roll back the last patch. Use /test to run your test suite and auto-fix failures. The conversational, iterative approach means you can refine requests and provide additional context at any point.

# Ask Daedalus to audit your project
> Can you audit this project and look for improvements

# Daedalus responds with clarifying questions:
# "Improvements could mean anything — what matters most?
# Performance? Readability? Security? Test coverage?"

# Provide focus
> Focus on performance and test coverage

# Run tests and auto-fix failures
> /test

# Commit the changes Daedalus made
> /commit

# Oops — roll back the last change
> /undo

# Manage chat sessions
> /session

# Save and quit
> exit

💡 Pro Tips

Pro Tip: Always run /index on large codebases before asking Daedalus to make changes — the symbol index is what enables accurate /find, /def, and /refs navigation, and it gives Daedalus a structural overview far more useful than reading random files.
Pro Tip: Use /extract liberally to encode tribal knowledge — architectural decisions, naming conventions, and business logic that aren't in the code. This dramatically improves the quality of Daedalus's suggestions over time.
Pro Tip: Leverage the multi-model architecture by letting Daedalus route tasks automatically: flash models (like DeepSeek-V4-Flash) handle quick completions, while larger models (like Mistral Large 3 or Qwen 480B) handle complex refactoring and architectural analysis.
Pro Tip: Keep /undo in your back pocket — it's your safety net. Daedalus makes surgical patch-based edits, so you can confidently experiment and roll back if a change doesn't land right.
Pro Tip: Use /context regularly to audit what Daedalus is actually looking at. Loading too many files dilutes focus; loading too few limits understanding. Be intentional about context.

⚠️ Common Pitfalls

Watch Out: Pitfall 1: Asking for a broad 'audit' without specifying priorities — Daedalus will push back and ask clarifying questions, which is the right behavior. Always narrow the scope first (e.g., 'focus on security vulnerabilities' or 'improve test coverage for the auth module').
Watch Out: Pitfall 2: Not running /index before navigation commands — /find, /def, and /refs depend on the FTS5 symbol index. Without it, Daedalus has to guess or read files linearly, which is slow and less accurate.
Watch Out: Pitfall 3: Loading too many files into context at once — this can dilute Daedalus's focus and lead to generic suggestions. Add only the files relevant to your current task.
Watch Out: Pitfall 4: Ignoring the /extract command — failing to encode tribal knowledge means Daedalus may suggest changes that violate unwritten project conventions or business rules.

❓ Frequently Asked Questions

How does Daedalus differ from GitHub Copilot or other autocomplete tools?

Daedalus is not an autocomplete feature — it is a persistent terminal-based AI service that builds a mental model of your explicitly loaded file context, indexes your entire codebase for symbol-level navigation, and engages in conversational dialogue to understand your priorities before suggesting changes. It also gives you full control with /commit and /undo, and supports multi-model routing across providers like DeepSeek, Mistral, Qwen, and Liquid.

What does the 30-second health check do?

The router runs health checks every 30 seconds to verify that Daedalus's connection to your project and its underlying models are functioning correctly. If something goes wrong — a model becomes unavailable, a connection drops — you are notified immediately rather than discovering the issue mid-task.

Can I use Daedalus for languages other than Python and Go?

Yes. Daedalus supports any language through its /project configuration command, which lets you set project-specific conventions and style guidelines. The multi-model architecture includes models like Mistral Large 3 and Kimi K2.6 that have strong multilingual capabilities, making Daedalus suitable for codebases in any language or framework.

What happens if a model is down or experiencing high latency?

Daedalus's multi-model architecture provides resilience. If one model is experiencing high demand or latency, Daedalus can seamlessly switch to an alternative model. Your workflow is not dependent on a single provider's uptime, which is critical for professional development environments.

How does /extract work and why should I use it?

The /extract command lets you manually pull facts from your session and store them for future reference. This is how you teach Daedalus tribal knowledge — architectural decisions, naming conventions, business logic, or project-specific patterns that are not obvious from reading the code alone. Using /extract dramatically improves the relevance and accuracy of Daedalus's suggestions over time.
