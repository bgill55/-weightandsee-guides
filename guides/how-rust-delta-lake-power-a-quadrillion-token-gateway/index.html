How Rust & Delta Lake Power a Quadrillion Token Gateway

This guide walks you through deploying Databricks Unity AI Gateway – a Rust‑powered proxy that routes LLM traffic, enforces security policies, and logs token usage in Delta Lake. You’ll learn how to start the gateway, configure endpoints, apply policies, and monitor token‑level analytics using the Python SDK and REST API.

🎯 Key Takeaways

  • 1The Unity AI Gateway provides a single control plane for all LLM calls, eliminating the need to embed model‑specific logic in your application.
  • 2A Rust proxy handles request inspection and smart routing at native speed, supporting hundreds of thousands of requests per second.
  • 3Token‑level usage is recorded in Delta Lake tables, enabling real‑time cost tracking and auditability.
  • 4Built‑in fallback routing automatically switches to an alternate model (e.g., Llama 4) when the primary model hits rate limits.
  • 5Policy‑driven guardrails enforce role‑based access, rate limits, and content safety without code changes.

📋 Prerequisites

  • Python 3.9+ with `pip` installed
  • Databricks workspace access and a personal access token with Unity Catalog permissions
  • Kubernetes cluster (or Docker) to host the stateless Rust proxy

Step 1: Install the Databricks SDK and configure authentication

Install the official Databricks Python SDK, then set your workspace URL and personal access token as environment variables. The SDK will be used to create endpoints, apply policies, and query usage data.

pip install databricks-sdk

# Set environment variables (Linux/macOS)
export DATABRICKS_HOST="https://adb-1234567890123456.18.azuredatabricks.net"
export DATABRICKS_TOKEN="dapiXXXXXXXXXXXXXXXXXXXXXXXX"

# Verify the SDK can connect
python - <<'PY'
import databricks.sdk as dbx
client = dbx.Client()
print('Connected to workspace:', client.host)
PY

Step 2: Deploy the Unity AI Gateway proxy

Run the gateway binary with a configuration file that points to your Kubernetes cluster and Delta Lake storage. The proxy starts in under fifteen seconds and begins listening for LLM traffic.

gateway start --config unity.yaml

# Example unity.yaml (replace placeholders)
# unity.yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: unity-gateway-config
data:
  delta_lake_path: "s3://my-delta-lake/tokens/"
  kubernetes_context: "my‑k8s‑cluster"
  allowed_providers: "openai,anthropic,custom"
3

Step 3: Create a unified LLM endpoint via the Python SDK

Define an endpoint that abstracts the underlying model provider. The SDK returns a URL you’ll use in your application instead of the provider’s direct API endpoint.

import databricks.sdk as dbx

gateway = dbx.UnityAIGateway()
endpoint = gateway.create_endpoint(
    name="my-llm",
    model="openai-chatgpt-5-point-5",
    provider="openai"
)
print('Endpoint URL:', endpoint.url)
4

Step 4: Apply a rate‑limit policy to control token spend

Create a JSON policy that caps daily token usage for a team or service. Attach the policy to the endpoint so the Rust proxy enforces it on every request.

policy = {
    "name": "rate-limit-team-a",
    "type": "rate_limit",
    "limit": 100000,
    "window": "day",
    "principal": "team_a"
}

gateway.apply_policy(endpoint_id=endpoint.id, policy=policy)
print('Policy applied to endpoint')
5

Step 5: Send a request through the gateway and monitor token usage

Use `curl` (or any HTTP client) to call the gateway URL. The proxy will route the request, apply policies, and log each token to Delta Lake. Then query the usage table to see real‑time cost analytics.

# Example request via curl
curl -X POST https://gateway.databricks.com/v1/completions \
     -H "Authorization: Bearer $DATABRICKS_TOKEN" \
     -d '{"model":"chatgpt-5.5","prompt":"Generate quest intro"}'

# Query token usage with the SDK
usage = gateway.query_usage(start="2026-07-01", end="2026-07-31")
for row in usage:
    print(f"User {row.user} spent {row.tokens} tokens costing ${row.cost:.2f}")

💡 Pro Tips

Pro Tip: Enable Delta Lake partitioning by date (`year=2026/month=07`) to keep query latency under a second for large token volumes.
Pro Tip: Configure multiple model providers in `unity.yaml` and assign a cost‑weight to each; the Rust proxy will automatically select the cheapest provider that satisfies the prompt.
Pro Tip: Use the gateway’s built‑in health endpoint (`/healthz`) to integrate with Kubernetes liveness/readiness probes for zero‑downtime scaling.

⚠️ Common Pitfalls

Watch Out: Pitfall 1: Forgetting to grant the gateway service principal read/write access to the Unity Catalog. Without proper permissions, the proxy cannot enforce policies or write token logs.
Watch Out: Pitfall 2: Mis‑formatting the policy JSON (e.g., using a string for the numeric limit). The SDK will raise a validation error and the policy will not be applied.

❓ Frequently Asked Questions

Can I add a custom model provider that isn’t listed in the default connectors?

Yes. Define a custom connector in `unity.yaml` with the target URL and authentication method, then reference its name when creating an endpoint via the SDK.

How does the gateway decide which model to route a request to?

The Rust proxy evaluates the request’s security tags and cost‑weight metadata, then selects the cheapest model that satisfies the policy constraints. If the primary model is rate‑limited, it falls back to the next eligible model.

Where are token usage logs stored and how can I query them?

Each request and response is streamed into Delta Lake as a Parquet entry. Use Spark SQL or the Python SDK’s `query_usage` method to aggregate tokens per user, project, or time window.

What happens if the gateway process crashes?

Because the proxy is stateless, Kubernetes will automatically restart the pod. All request logs are persisted in Delta Lake, so no data is lost.

Is there a way to monitor fallback events in real time?

Enable the gateway’s metrics endpoint (`/metrics`) and integrate with Prometheus; the metric `fallback_count` increments each time a request is rerouted to an alternate model.
