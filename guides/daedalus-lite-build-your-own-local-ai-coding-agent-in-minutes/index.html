Daedalus-Lite: Build Your Own Local AI Coding Agent in Minutes

This guide walks you through setting up Daedalus-Lite, a zero‑dependency TypeScript starter template for building a local AI coding assistant. You will clone the repository, configure it to use either cloud or offline LLMs, customize branding, and finally package the CLI as a standalone binary you can publish or sell.

🎯 Key Takeaways

  • 1Daedalus-Lite runs completely locally, supporting offline models like Ollama and LM Studio.
  • 2An in‑memory router abstracts multiple LLM providers behind a single ModelResponse interface.
  • 3The built‑in REPL offers slash commands (/help, /model, /clear, /exit) for interactive pair‑programming.
  • 4Full rebranding lets you change names, colors, and branding assets to create a market‑ready product.
  • 5You can compile the CLI to a standalone executable with `pkg` and publish it to npm or distribute it without Node installed.
  • 6Middleware injection (`router.use`) enables logging, rate‑limiting, or custom system prompts.
  • 7Three monetization tracks let you sell PDFs, pre‑configured CLIs, or full consulting packages.

📋 Prerequisites

  • Node.js v20+ (required for native fetch and ESM support) and npm v10 installed.
  • Basic familiarity with TypeScript, npm scripts, and command‑line usage.

📝 Step-by-Step Guide

1

Step 1: Clone the Repository and Install Dependencies

Open a terminal, clone the public Daedalus‑Lite repo, navigate into the folder, and install the required packages. The template has zero runtime dependencies, but you still need the dev tools for building and testing.

git clone https://github.com/bgill55/daedalus-lite.git
cd daedalus-lite
npm install
2

Step 2: Build the TypeScript Project

Compile the TypeScript source to JavaScript using the provided npm script. This step also generates the type‑safe REPL entry point.

npm run build
3

Step 3: Configure Your LLM Endpoint

Edit `src/config.ts` (or create a `.env` file) to point the router at your preferred model. For offline usage, ensure Ollama or LM Studio is running on the default ports; for cloud models, add the API key and endpoint URL. Example for Ollama: ```ts export const DEFAULT_MODEL = { provider: "ollama", endpoint: "http://localhost:11434/api/chat", model: "codegemma" }; ```

// .env for OpenAI (optional)
OPENAI_API_KEY=sk-************************

// src/config.ts example for local model
export const DEFAULT_MODEL = {
  provider: "ollama",
  endpoint: "http://localhost:11434/api/chat",
  model: "codegemma"
};
4

Step 4: Run the Interactive REPL and Test Commands

Start the CLI with `npm start`. The REPL will launch, allowing you to type code snippets. Use slash commands to switch models (`/model`), clear history (`/clear`), or view help (`/help`). Verify that responses come from the configured LLM.

npm start

# Inside the REPL
> console.log('Hello world');
/ model ollama
/ clear
/ help
5

Step 5: Rebrand and Compile to a Standalone Binary

Update branding constants in `src/branding.ts` (name, primary/accent colors). Then use `pkg` to generate executables for your target platforms. The resulting binaries can be distributed without requiring Node on the user's machine.

// src/branding.ts
export const BRAND = {
  name: "MyAI‑Assistant",
  colors: { primary: "#1E3A8A", accent: "#F59E0B" }
};

# Compile binaries (example for Windows and macOS)
npx pkg . --targets node20-win-x64,node20-macos-x64 -o bin/daedalus

💡 Pro Tips

Pro Tip: Add custom middleware with `router.use` to inject logging, rate‑limiting, or system prompts before each request.
Pro Tip: When compiling with `pkg`, include a postinstall script to copy any static assets (e.g., brand logos) into the binary's output folder.
Pro Tip: Use TypeScript path aliases (`paths` in `tsconfig.json`) to keep imports tidy when you expand the project with additional modules.

⚠️ Common Pitfalls

Watch Out: Pitfall 1: Using Node versions older than 20 will break native fetch calls. Always verify `node -v` before building.
Watch Out: Pitfall 2: Forgetting to set the correct endpoint for local models results in connection errors. Double‑check that Ollama or LM Studio is running and that the port matches the config.

❓ Frequently Asked Questions

Do I need API keys to use local models like Ollama or LM Studio?

No. Local models run entirely offline and do not require any API keys. Only cloud providers (OpenAI, Anthropic) need keys.

How can I add custom middleware to modify requests?

Use the router’s `use` method. For example: ```ts router.use((req, res, next) => { console.log(`Routing request to ${req.model}`); next(); }); ```

Can I publish my branded CLI to the public npm registry?

Yes. After rebranding (name, colors, license), run `npm publish` or use `npm login` followed by `npm publish`. Make sure your package name is unique.

What platforms does `pkg` support for compiled binaries?

`pkg` can target Windows, macOS, and Linux for the Node.js version you specify (e.g., `node20-win-x64`). Include the desired targets in the `--targets` flag.

How do I switch the active LLM model at runtime?

Inside the REPL, use the `/model` command followed by the provider name, e.g., `/model ollama` or `/model openai`. The router updates the active endpoint accordingly.
