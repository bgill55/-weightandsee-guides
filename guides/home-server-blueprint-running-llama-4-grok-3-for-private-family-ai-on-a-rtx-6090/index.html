Home Server Blueprint: Running Llama 4 & Grok 3 for Private Family AI on a RTX 6090

This guide provides a comprehensive blueprint for building a privacy-first, local AI family server using an RTX 6090 to run Llama 4 and Grok 3. It covers setting up a Docker-based stack with Flowise for visual prompt engineering and n8n for workflow automation to handle tasks like email parsing and calendar syncing. The focus is on creating a secure, offline environment that processes family logistics without sending data to the cloud.

📝 Step-by-Step Guide

1

Step 1: Configure Docker and Local Networking

Create a docker-compose.yml file to orchestrate your AI services. This file defines a virtual LAN where your models, interface, and automation tools communicate securely. Ensure you map the local port 11434 for your Llama 4 instance and port 3000 for Flowise to keep traffic off the public internet.

version: '3.8'
services:
  flowise:
    image: flowiseai/flowise
    ports:
      - "3000:3000"
    environment:
      - PORT=3000
  # Assuming Ollama or similar inference engine for Llama 4 on port 11434
  llama-engine:
    image: ollama/ollama
    ports:
      - "11434:11434"
    volumes:
      - ollama_data:/root/.ollama
volumes:
  ollama_data:
2

Step 2: Set Up Flowise with Local Models

Launch Flowise and drag a 'Chatbot' node and a 'Llama 4' model node onto the canvas. In the Llama 4 node configuration, set the Base URL to `http://host.docker.internal:11434`. This address allows the containerized Flowise app to communicate with the inference engine running on your host machine.

Configuration:
Base URL: http://host.docker.internal:11434
Model Name: llama-4-70b

Note: Add a 'Prompt Template' node before the model to inject system instructions.
3

Step 3: Build Email Parsing Workflow in n8n

Create a workflow in n8n starting with a 'Gmail Trigger' node configured to watch a specific folder (e.g., 'School Updates') via IMAP. Connect this to an 'HTML Extract' node to strip signatures and headers, converting the email body into clean text for processing.

Node 1: Gmail Trigger
- Event: New Email
- Folder: School Updates

Node 2: HTML Extract
- Operation: Extract HTML Content
- Output Property: cleanText
4

Step 4: Integrate LLM for Data Extraction

Pass the cleaned text from the HTML Extract node to your Llama 4 node within n8n. Configure the prompt to strictly request a JSON response containing dates, times, and events. This structured output is necessary for the next step to function correctly.

Prompt:
"Extract all dates, times, and event names from the following text. Return the result strictly as a JSON object with the structure: {"events": [{"date": "YYYY-MM-DD", "time": "HH:MM", "description": "String"}]}.

Text: {{ $json.cleanText }}"
5

Step 5: Sync to Google Calendar

Connect the JSON output from the Llama 4 node to a 'Google Calendar' node in n8n. Authenticate the node with your Google account and map the JSON fields (date, time, description) to the calendar event properties to automatically add the family schedule.

Node: Google Calendar
- Operation: Create Event
- Title: {{ $json.events[0].description }}
- Start Time: {{ $json.events[0].date }}T{{ $json.events[0].time }}

💡 Pro Tips

Pro Tip: Use `host.docker.internal` as the Base URL in Flowise so containers can reliably resolve the host machine's IP address.
Pro Tip: Leverage the RTX 6090's VRAM to run multiple models simultaneously; for example, let Grok 3 handle background scheduling while Llama 4 manages active chat.
Pro Tip: Always validate the JSON schema in your n8n workflow before the calendar node to prevent automation failures if the LLM hallucinates the format.

⚠️ Common Pitfalls

Watch Out: Port Mapping Issues: If you use `localhost` instead of `host.docker.internal` in the container configuration, the connection to the GPU model will fail.
Watch Out: Prompt Inflexibility: If the LLM outputs natural language instead of JSON, the n8n workflow will break; ensure your prompt instructions are rigid and include examples of the desired format.

❓ Frequently Asked Questions

Why is port 11434 used in the configuration?

Port 11434 is the default port for local LLM inference engines (like Ollama), allowing the web interface to communicate with the model server.

Can I run this on a GPU with less than 48GB of VRAM?

You may experience significant slowdowns or need to use smaller, less capable models, as the 70B parameter model at 4-bit quantization requires substantial memory for fast inference.

How does the system ensure data privacy?

By using Docker port mapping and `host.docker.internal`, all data traffic stays within the local machine. No data is sent to the cloud for inference after the initial model download.
