Watch Out: Pitfall 1: Assuming software optimization solves all bottlenecks. Often, the limiting factor remains the physical memory bandwidth of the underlying hardware (e.g., PCIe bus speed).
Watch Out: Pitfall 2: Ignoring quantization compatibility. Simply quantizing a model without updating related components (like activation functions or normalization layers) can lead to significant accuracy degradation.
Watch Out: Pitfall 3: Over-relying on theoretical complexity reduction. Real-world performance is often limited by constant factors, hardware overhead, and data transfer time, which must be measured empirically.

❓ Frequently Asked Questions

Is the Transformer architecture fundamentally limited by quadratic complexity?

Yes, standard self-attention has $O(N^2)$ complexity with respect to sequence length ($N$). Optimizations like FlashAttention and linear attention methods aim to reduce this to near-$O(N)$ or $O(N ext{ log } N)$.

What is the primary difference between optimizing for training versus inference?

Training focuses on maximizing computational throughput (FLOPs) across massive datasets. Inference focuses on minimizing latency and memory bandwidth usage, as it must run efficiently on existing hardware constraints.

How does memory bandwidth limit LLM scaling?

Large models often require reading massive weight matrices repeatedly (especially during inference). If the GPU/TPU cannot stream these weights and activation tensors quickly enough from VRAM, the processing unit stalls, making computation time limited by data transfer speed rather than raw compute power.
