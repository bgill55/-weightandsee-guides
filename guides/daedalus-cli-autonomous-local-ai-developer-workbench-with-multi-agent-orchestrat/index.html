Step 1: Clone the Daedalus repository and install Go & Node dependencies

Open a terminal, clone the official Daedalus CLI repo, then install the Go modules and Node packages required for the workbench. The Go build provides the CLI binary while npm installs the TypeScript test runner used later.

git clone https://github.com/bgill55/daedalus.git
cd daedalus
# Install Go dependencies
go mod tidy
# Install Node dev dependencies (for version.ts & tests)
npm install

Use the built‑in `/spec` command to start a spec that will create a helper function in `src/version.ts`. The CLI will prompt you for a description; copy the exact string shown in the video.

daedalus spec "Add a helper function to validate version string format and export it in version.ts"

Step 3: Implement the `isValidSemver` helper in `src/version.ts`

Create `src/version.ts` (or edit the generated file) and add a strict SemVer validator that returns a boolean. The implementation uses a regular expression that matches `MAJOR.MINOR.PATCH` with optional pre‑release identifiers.

export function isValidSemver(v: string): boolean {
  const semverRegex = /^(0|[1-9]\d*)\.(0|[1-9]\d*)\.(0|[1-9]\d*)(?:-[A-Za-z0-9.-]+)?$/;
  return semverRegex.test(v);
}
4

Step 4: Write Jest tests in `src/version.test.ts`

Add a test file that imports the helper and checks both positive and negative cases. The video shows a table of valid and invalid strings; replicate those to ensure coverage of edge cases like leading zeros and missing components.

import { isValidSemver } from './version';

describe('isValidSemver', () => {
  const valid = [
    '0.0.0',
    '1.0.0',
    '12.34.56',
    '1.93.0-canary',
    '2.0.1-beta.2',
    '123.456.789'
  ];
  const invalid = [
    '2',
    '4',
    'Ba.285',
    'e1.2.2',
    '1.02.3',
    '1.2.03',
    '1.0.0-'
  ];

  test.each(valid)('accepts %s', v => {
    expect(isValidSemver(v)).toBe(true);
  });

  test.each(invalid)('rejects %s', v => {
    expect(isValidSemver(v)).toBe(false);
  });
});
5

Step 5: Run Daedalus’s pre‑commit review gates and merge the PR

Daedalus automatically runs a suite of checks before allowing a merge. Execute the CLI’s review command, which will invoke type‑checking (`npx tse`), linting (`npm run lint`), and the test suite (`npm test`). Resolve any failures, then push the changes; the automated PR reviewer will report a green status if everything passes.

daedalus review
# Manual equivalents if you prefer:
npx tse
npm run lint
npm test
# If all pass, commit and push
git add .
git commit -m "Add strict SemVer validator"
git push origin feature/semver-validator

⚠️ Common Pitfalls

Watch Out: Pitfall 1: Using a permissive regex that allows leading zeros – the strict regex above prevents versions like `01.0.0`.
Watch Out: Pitfall 2: Forgetting to export the function from `version.ts`, which leads to import errors in the test file.

❓ Frequently Asked Questions

Do I need both Go and Node installed to use Daedalus CLI?

Yes. Go provides the core Daedalus binary, while Node/npm are required for the TypeScript utilities and test runner shown in the tutorial.

Can I replace the FreeLLMAPI router with another LLM provider?

Absolutely. The router is configured via a JSON file; simply swap the endpoint URL and authentication token for the new provider.

What does the `daedalus review` command actually do?

`daedalus review` triggers the pre‑commit gates: it runs type‑checking (`npx tse`), linting (`npm run lint`), and the test suite (`npm test`). If any step fails, the PR reviewer marks the commit as failed.

Why does the validator return a boolean instead of throwing errors?

Returning a boolean keeps the function pure and easy to use in both runtime checks and unit tests. If you need detailed error messages, wrap the call in a helper that inspects the regex match groups.

How can I add more specs to the Daedalus workbench?

Run `daedalus spec "Your description"` for each new feature. The CLI will generate scaffolding files and automatically register them with the project’s orchestration layer.
