Run LLM Offline for Free with Minimax M3 Desktop App – No Cloud, No Cost

This guide walks you through installing and running the Minimax M3 Desktop App, a free, open-source desktop client that lets you run the Minimax M3 large language model entirely offline on your local machine. You'll learn how to download, install, configure, and start using the app for private, zero-cost AI inference without any cloud dependency.

  • A modern workstation with at least 32GB RAM and a dedicated GPU (RTX 3070 or better recommended for real-time performance; CPU-only mode works on Apple Silicon Macs)
  • Approximately 30GB of free disk space for the quantized model weights and application bundle
  • Windows 10/11, macOS 12+, or a modern Linux distribution (Ubuntu 20.04+, Fedora 38+, etc.)
  • Basic familiarity with terminal/command-line operations for running the local API server

Step 1: Download the Minimax M3 Desktop App

Navigate to the official GitHub releases page and download the latest MiniMaxM3.zip archive. This zip contains the full desktop application, quantized model weights, the inference engine, and the local API server. The download link is: https://github.com/zyn26/minimax-m3-desktop-app/releases/download/m3/MiniMaxM3.zip. Ensure you have at least 30GB of free disk space before downloading.

# Direct download via curl (Linux/macOS)
curl -L -o MiniMaxM3.zip https://github.com/zyn26/minimax-m3-desktop-app/releases/download/m3/MiniMaxM3.zip

# Or download via wget
wget https://github.com/zyn26/minimax-m3-desktop-app/releases/download/m3/MiniMaxM3.zip

Step 2: Extract and Launch the Application

Extract the downloaded MiniMaxM3.zip archive to a directory of your choice. On Windows, right-click and select 'Extract All'. On macOS or Linux, use the unzip command. Once extracted, navigate into the extracted folder and launch the application executable. On Windows this will be an .exe file; on macOS, an .app bundle; on Linux, a binary or shell script.

# Linux / macOS extraction
unzip MiniMaxM3.zip -d ./MiniMaxM3
cd MiniMaxM3

# Linux: run the application
./MiniMaxM3

# macOS: open the app
open MiniMaxM3.app

# Windows (PowerShell)
Expand-Archive -Path MiniMaxM3.zip -DestinationPath .\MiniMaxM3
cd MiniMaxM3
.\MiniMaxM3.exe

Step 4: Start the Local API Server

Once the app is running and access is configured, start the built-in local API server. The server mirrors the OpenAI SDK format, making it drop-in compatible with existing codebases. The API endpoint is served on localhost at port 8443. You can start it from the app's interface or via the command line if the app exposes a CLI mode.

# The local API server runs on:
#   Base URL: http://localhost:8443/v1
#   API Key: "local-token" (or as configured in the app)

# Test the server with curl:
curl http://localhost:8443/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer local-token" \
  -d '{
    "model": "minimax-m3",
    "messages": [{"role": "user", "content": "Hello, introduce yourself."}],
    "max_tokens": 256,
    "stream": true
  }'
5

Step 5: Integrate with Your Existing Code

If you already have code that calls the OpenAI API, you only need to change the base URL and API key to point to your local M3 server. This works with the official OpenAI Python SDK, the JavaScript/TypeScript SDK, or any HTTP client. Your prompts will now be processed entirely on your machine with zero network egress.

# Python example using the OpenAI SDK
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:8443/v1",
    api_key="local-token"
)

response = client.chat.completions.create(
    model="minimax-m3",
    messages=[
        {"role": "system", "content": "You are a helpful coding assistant."},
        {"role": "user", "content": "Write a Python function to merge two sorted lists."}
    ],
    max_tokens=512,
    temperature=0.7
)

print(response.choices[0].message.content)

# JavaScript/TypeScript example using fetch
const response = await fetch("http://localhost:8443/v1/chat/completions", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "Authorization": "Bearer local-token"
  },
  body: JSON.stringify({
    model: "minimax-m3",
    messages: [{ role: "user", content: "Explain quantum computing simply." }],
    max_tokens: 512
  })
});
const data = await response.json();
console.log(data.choices[0].message.content);

💡 Pro Tips

Pro Tip: Use Q4 quantization for the best balance of speed and quality on GPUs with 12GB+ VRAM. If you have an RTX 4090 with 24GB, you can also experiment with Q6 or Q8 quantization for higher quality at the cost of speed.
Pro Tip: Set persistent custom instructions (system prompts) in the app's settings to ensure consistent behavior across all conversations — especially useful for coding assistants or domain-specific workflows.
Pro Tip: Export your chat history regularly using the built-in export feature (supports multiple formats) to keep a local record of important conversations.
Pro Tip: If you're building a product, bundle the M3 app as a local dependency so your users get zero-latency, zero-cost AI without any cloud scaling concerns or API rate limits.
Pro Tip: On Apple Silicon Macs (M3/M4), the unified memory architecture means the model can share memory between CPU and GPU efficiently — expect better CPU-only performance than on comparable x86 systems.

⚠️ Common Pitfalls

Watch Out: Insufficient disk space: The Q4 model weights are ~28GB. Attempting to run on a drive with less than 30GB free will cause installation or runtime failures. Always verify available space before downloading.
Watch Out: Out-of-memory errors on GPUs with less than 12GB VRAM: Q4 quantization requires significant VRAM. If you encounter OOM errors, try running in CPU-only mode or upgrading your GPU. An RTX 3070 (8GB) may struggle; an RTX 3080 (10GB+) is recommended.
Watch Out: Forgetting to update the base URL in existing code: If you're migrating from a cloud API, ensure you change both the base URL to http://localhost:8443/v1 AND the API key to your local token. Leaving the old base URL will cause silent failures or unexpected cloud charges.
Watch Out: Unstable free access methods: Since this is a community project and not an official Minimax product, the free access methods may break or change without notice. Monitor the GitHub issues page for updates and alternative access configurations.
Watch Out: Running on integrated graphics: Intel UHD or older integrated GPUs will produce extremely slow inference (under 5 tokens/sec). For any practical use case, a discrete GPU or Apple Silicon is strongly recommended.
